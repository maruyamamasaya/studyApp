# Learnleaf UI刷新 実装プロンプト

iOS版Learnleafの利便性と見た目を、以下の合意に沿って改善してください。

## 目的と優先順位

まず見た目の一貫性を整える。学習の再開はホームの主役にしない。正方形タイルが好みであり、MyMusicのHomeCarouselSection/HomeItemTileの情報階層と横スクロールを参考にする。Living Aurora UIの既存Web/iOSデザイン資料と実装を一次情報として参照し、Learnleafに適した静かなテーマを反映する。

## 画面構成

下部タブを「記事・聴く・検索・フォルダ・設定」の5つにする。「聴く」に番組と個別音声をまとめ、番組詳細・作成・削除・並べ替え・再生順編集への導線を維持する。フォルダは独立タブとして残す。

検索の入口を検索タブへ集約する。記事・音声・番組を横断検索でき、対象、タグ、階層フォルダ、お気に入り、コレクション、読了/聴取状態、音声の有無を組み合わせて絞り込める。条件、結果件数、リセットを明示する。タグや保存一覧から検索する場合は共通検索へ条件を引き継ぐ。編集用の記事/音声選択画面のローカル検索は維持してよい。

本文検索は大量のHTTPS取得を伴うため、明示操作で開始し、取得状況・取消・取得失敗を表示する。取得できなかった記事を検索済みと扱わない。既存のhash照合・キャッシュ・取得制限を維持する。

## デザイン

Living Auroraの暗い空間、Violet/Cyanの局所光、静かなガラス面と細い縁の反射を共通トークンにする。全要素を発光させず、本文の背後は静かにする。明暗両モードとアクセシビリティを維持する。派手な常時アニメーションは不要。

記事と番組のカードは正方形タイルを基準にし、角丸・余白・タイトルと補足の階層を揃える。ホームはピックアップとお気に入りを中心にする。検索結果と編集画面では長いタイトルの比較を優先する。小さめの文字、約2.5枚が見える既存カルーセル、Dynamic Typeを尊重する。

## 制約と完了条件

未commitの既存変更を保持し、記事原本、Web UI、保存形式、同期契約を不用意に変更しない。再生バーが本文や操作を覆わない構造を維持する。共通デザインを記事・聴く・検索・フォルダ・設定へ適用し、既存機能への導線を維持する。Simulator運用規則に従いビルド・必要なテスト・画面確認を行う。実機配布・commit/pushは別途指示があるまで行わない。CURRENT/ARCHITECTURE/sessionを更新し、未検証事項を明記する。

## 2026-10-06 性能調査後の追加指示

記事カードはタイトル中心とし、本文冒頭の抜粋表示とそのための自動取得を廃止する。本文は記事を開いた時、または明示的な全文検索操作時に取得する。ピックアップは順位hashを事前計算し、入力が変わった時だけUIスレッド外で選出して結果を保持する。
