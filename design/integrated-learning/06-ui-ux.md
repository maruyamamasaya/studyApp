# 6. UI・UX設計書
状態: 提案。既存UI根拠は[01](01-current-system.md)。

## 統合の入口

iOSの下部タブ「記事・聴く・検索・フォルダ・設定」を増やさない。記事詳細に「関連資料」を追加し、図解・文書・発表を同じNavigationStackで開く。検索は記事/音声/番組を維持し、資料フィルターを段階追加する。Webは既存sidebar・検索・本文を維持し、本文内thumbnail/末尾資料一覧→viewerを開く。資料ライブラリは既存の検索/フォルダ導線からアクセスする案。

記事・図解・発表・文書はviewer種別であり、4つの常設ナビを必須にしない。既存コレクションは記事ID限定のまま維持し、資料保存は初期に別一覧。将来混在collectionにするならschema移行と旧backup復元を先に設計する。

## 画面の仕様案

| 画面 | 操作 | スマホ配慮 |
| --- | --- | --- |
| 関連資料一覧 | title/type/thumb/容量/保存状態、タグ検索、記事へ戻る | 小さなthumbnail、本文の読み込みを先行 |
| 図解 | fit/reset/zoom/fullscreen/説明/関連記事/export | pinch+ボタン、panと画面戻りgestureの競合を検証 |
| PDF/Office | ページ番号・移動・文字検索・原本情報・派生状態 | 今のページ中心、縦scroll、拡縮操作を常時占有しない |
| 発表 | 前後/ページ一覧/図解拡大/ノート/全画面 | 横向き推奨、縦でもfit、swipeのボタン代替 |
| import | 複数選択、形式/容量/重複表示、処理進捗、結果 | iOS Files、dropがない端末も同機能 |
| slide編集 | outline並替、分割/結合、theme、notes、記事更新比較 | 初期はPC優先、スマホは閲覧と軽い確認 |

## 状態とエラー

取得中・未保存・端末保存済み・保存済み旧版・原本のみ・変換待ち・抽出のみ・変換失敗・未対応・公開対象外を区別する。原本hash更新時は「記事/原本が更新されています」を表示。エラーから再試行/原本書き出し/代替PDF/前版に戻るを可能な範囲で提供する。

削除操作はcache削除、端末原本削除、Vault原本削除を異なる操作にする。私的import後は「この端末だけに保存」と表示し、公開するには別工程が必要と分かるようにする。公開URLへの資料アップロード画面は初期には設けない。

## 発表者ノートと学習記録

PCは別windowの発表者ノートを候補にし、popup拒否時は手動で開く。スマホ単一画面のノートは発表表示へ重ねず別sheet、共有画面に出る可能性を案内する。私的ノートは公開HTML/PDFから既定除外し、公開deck.jsonにも含めない。

既存の記事学習時間計測は画面/タブ/背景状態に連動。資料閲覧時間を追加する場合は記事時間と二重計測しない専用resource sessionを設計する。Phase1では資料時間の自動加算を行わない。

## アクセシビリティと評価

viewerを閉じたら元リンクへfocus/scroll復元。図解説明・番号付きslide・PDF抽出text・UIラベルを読み上げ可能にし、視覚図だけで理解を要求しない。図解dark版がない場合は余白付き明色面で表示する。縮小で文字が読めなければ説明文へ移れる。既存テーマ、ミニプレイヤー、Dynamic Typeとの重なりを検証する。

受入シナリオは記事→図解拡大→関連記事→戻る、Files import→失敗通知→再試行、記事更新→deck差分→保留、機内モード→保存資料閲覧。実機でタップ数・待ち時間・回転・文字拡大を測定し、スクリーンショットだけで合格にしない。
