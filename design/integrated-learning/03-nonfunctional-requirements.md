# 3. 非機能要件定義書
状態: 未測定の受入目標案。上限は実機評価後に確定。

## 性能と容量

| 項目 | 初期目標案 | 検証方法 |
| --- | --- | --- |
| 図解一覧 | 1,000件で初回metadata表示2秒以内、thumbnail遅延読込 | iPhone/iPad Safari、Learnleaf、PC、冷キャッシュ/低速通信 |
| 描画 | 操作中に100ms超の主スレッド停止を継続発生させない | Instruments/ブラウザーperformanceでズーム/スクロール |
| SVG | 原本2MiB、要素20,000以下、PNG出力最大16MP | 小型/巨大path/filter/埋め込み画像の比較 |
| Office | 原本50MiB/件、ZIP展開200MiB・10,000 entries・比率100以下 | 圧縮爆弾・大量画像・多数ページ、超過を段階拒否 |
| PDF | 100MiB/件、500ページを初期上限案 | 現在ページ±1だけ描画、遠いcanvas破棄 |
| 取り込み | 1 batch 20件/200MiB、変換は1件ずつ、取消可能 | 途中失敗/キャンセル/端末容量不足 |
| ローカル変換 | 1 job timeout 120秒、出力/CPU/メモリ上限を環境別設定 | 制限超過は失敗、原本/前版を保持 |
| 端末保存 | 初期quota 500MiB案、空き容量確認、保存済み量を表示 | 容量不足で既存データを壊さない |

巨大データを全件Data/DOMへ展開しない。workerへ送れる解析はworker、iOSはactor/背景タスクへ分離。描画倍率と同時canvas数を制限する。上限は公開資産・端末import双方に適用し、解凍中も監視する。

## オフラインと整合性

Learnleafの検証済みcatalog/本文保存を再利用し、リソースは明示ダウンロード・容量表示・削除を追加。ネット接続中にhash不一致なら通信障害fallbackで隠さない。旧版は「保存済み旧版」として閲覧できても最新版とは扱わない。

Webはviewerとライブラリを自己配信し、将来Service Worker/Cache StorageとIndexedDBの版管理でoffline化する。現行Webには未実装で、ブラウザーの保存削除・quotaは避けられない。私的原本は自動削除対象にせず、書き出しを用意する。学習記録の削除と記事/派生cache削除を分離する。

## 利用品質

WCAG 2.2 AAを目標とする。すべてのスワイプ/ピンチ機能にボタン/キーボード代替、フォーカス復元、VoiceOverと読み上げ順、十分なcontrast、図解のaltと長文説明、PDFの検索用テキストを用意する。画像slideのみの出力はアクセシビリティ低下を明示。全画面拒否・縦画面でも閲覧できる。Reduce Motionでアニメーション停止。

## 保守・互換性

既存v1配信/学習backupを変更しない。新索引はschemaVersionとfixtureを持ち、未知版は明示拒否。依存は固定版とLICENSE/NOTICEを管理し、導入時と更新時に脆弱性確認。ビルド/変換ログは原本内容や個人パスを不用意に保存しない。失敗件数、converter版、入力hash、所要時間で再現可能にする。

セキュリティ受入は[09](09-security.md)。実装時は既存Node回帰テストと必要なviewer/Swiftテストを追加し、Simulator運用ルールを守る。今の設計文書作成ではiOS全体テストは実行しない。
