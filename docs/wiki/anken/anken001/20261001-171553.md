## 1. 概要

APIを理解するうえで、

- HTTP
    
- JSON
    

は非常に重要です。

簡単にいうと、

**HTTP = データをやり取りするための通信ルール**

**JSON = やり取りするデータの書き方**

です。

例えば、

Web画面  
→ HTTPでRequest送信  
→ JSONで質問データを渡す  
→ API処理  
→ JSONでResponse返却

という流れになります。

---

# 2. HTTPとは

HTTPは、

HyperText Transfer Protocol

の略です。

Webブラウザやアプリとサーバーが、

**どのように通信するかを決めたルール**

です。

例えば、

ブラウザ  
→ HTTP Request  
→ Server

Server  
→ HTTP Response  
→ ブラウザ

という形で通信します。

---

## 3. HTTP Request

ClientからServerへ送る通信を、

HTTP Request

と呼びます。

Requestには主に、

- Method
    
- URL
    
- Header
    
- Body
    

があります。

例えば、

POST /api/ask

というAPIへ質問を送る場合です。

---

## 4. HTTP Response

ServerからClientへ返す通信を、

HTTP Response

と呼びます。

Responseには主に、

- Status Code
    
- Header
    
- Body
    

があります。

例えば、

200 OK

と一緒に、

回答内容

をJSONで返します。

---

## 5. HTTP Method

Requestには、

「何をしたいのか」

を表すMethodがあります。

代表的なものは、

- GET
    
- POST
    
- PUT
    
- PATCH
    
- DELETE
    

です。

---

## 6. GET

データを取得するときに使います。

例えば、

GET /documents

なら、

文書一覧を取得する

というイメージです。

---

## 7. POST

データを送信したり、処理を実行するときに使います。

例えばRAGなら、

POST /ask

で質問を送ります。

---

## 8. PUT

データ全体を更新するときに使われることがあります。

例えば、

PUT /users/123

で、

ユーザー123の情報を全体更新します。

---

## 9. PATCH

一部分だけ更新するときに使います。

例えば、

PATCH /users/123

で、

表示名だけ変更する

ような処理です。

---

## 10. DELETE

データを削除するときに使います。

例えば、

DELETE /documents/123

です。

---

## 11. URL

HTTP Requestでは、

どこへアクセスするか

をURLで指定します。

例えば、

[https://example.com/api/v1/documents/123](https://example.com/api/v1/documents/123)

です。

大きく、

- Protocol
    
- Host
    
- Path
    

などに分かれます。

---

## 12. Protocol

例えば、

https://

の部分です。

HTTPを暗号化して通信する方式が、

HTTPS

です。

現在のWeb APIでは通常HTTPSを利用します。

---

## 13. Host

例えば、

example.com

の部分です。

どのServerへ接続するかを表します。

---

## 14. Path

例えば、

/api/v1/documents/123

の部分です。

Server内のどのAPIを呼ぶかを表します。

---

## 15. HTTP Header

Headerは、

RequestやResponseに付ける補助情報

です。

例えば、

- Content-Type
    
- Authorization
    
- Accept
    

などがあります。

---

## 16. Content-Type

Bodyのデータ形式を表します。

例えば、

Content-Type: application/json

なら、

「BodyはJSON形式です」

という意味です。

---

## 17. Authorization

認証情報を送るために使います。

例えば、

Authorization: Bearer xxxxx

のようにTokenを送ります。

---

## 18. Accept

Clientが、

どの形式でResponseを受け取りたいか

を伝えるHeaderです。

例えば、

Accept: application/json

です。

---

## 19. HTTP Body

RequestやResponseの本文です。

POST APIでは、

BodyにJSONを入れることがよくあります。

例えば、

```
{
  "question": "バックアップの保存期間は？"
}
```

です。

---

# 20. JSONとは

JSONは、

JavaScript Object Notation

の略です。

システム間でデータをやり取りするときによく使われる、

**シンプルなデータ表現形式**

です。

APIでは非常によく使われます。

---

## 21. JSONの基本形

JSONは、

KeyとValue

の組み合わせでデータを表します。

例えば、

```
{
  "name": "Taro",
  "age": 30
}
```

です。

nameとageがKey、

"Taro"と30がValueです。

---

## 22. JSON Object

波括弧、

{ }

で囲まれたデータをObjectとして扱います。

例えば、

```
{
  "document_id": "DOC001",
  "title": "Backup Rule"
}
```

です。

Pythonでは、

dict

に近い構造です。

---

## 23. JSON Array

複数の値を並べる場合は、

[ ]

を使います。

例えば、

```
{
  "tags": [
    "RAG",
    "AI",
    "Python"
  ]
}
```

です。

Pythonでは、

list

に近い構造です。

---

## 24. JSONで使える値

JSONでは主に、

- string
    
- number
    
- boolean
    
- object
    
- array
    
- null
    

を扱えます。

---

## 25. String

文字列です。

例えば、

```
{
  "name": "RAG"
}
```

です。

文字列は、

" "

で囲みます。

---

## 26. Number

数値です。

例えば、

```
{
  "top_k": 5
}
```

です。

数値にはダブルクォートを付けません。

---

## 27. Boolean

真偽値です。

JSONでは、

true  
false

を使います。

例えば、

```
{
  "enabled": true
}
```

です。

---

## 28. null

値がないことを表します。

例えば、

```
{
  "error": null
}
```

です。

Pythonでは、

None

に近いものです。

---

## 29. JSONのネスト

Objectの中にさらにObjectを入れられます。

例えば、

```
{
  "user": {
    "id": "U001",
    "role": "admin"
  }
}
```

です。

このように階層構造を作れます。

---

## 30. JSONとPython

PythonではJSONとdictを相互変換できます。

例えば、

```
import json

data = {
    "question": "バックアップの保存期間は？"
}

json_text = json.dumps(
    data,
    ensure_ascii=False,
)
```

これでPythonのdictをJSON文字列へ変換できます。

---

## 31. JSONをPythonへ変換

逆にJSON文字列をdictへ変換できます。

```
import json

json_text = '''
{
  "question": "バックアップの保存期間は？"
}
'''

data = json.loads(json_text)

print(data["question"])
```

となります。

---

# 32. HTTPとJSONの関係

HTTPとJSONは別のものです。

HTTPは、

**通信方法**

JSONは、

**データ形式**

です。

例えば、

HTTP POST

を使って、

JSONデータ

を送ります。

---

## 33. RAG APIのRequest例

例えば、

POST /api/v1/ask

へ質問を送ります。

HTTP Body：

```
{
  "question": "バックアップの保存期間は？"
}
```

Server側ではこのJSONを読み取り、

question

をRAG処理へ渡します。

---

## 34. RAG APIのResponse例

RAG処理が完了すると、

```
{
  "answer": "バックアップは30日間保存します。",
  "sources": [
    {
      "document": "backup-rule.pdf",
      "page": 12
    }
  ]
}
```

のように返せます。

---

## 35. HTTP Request全体のイメージ

例えば、

```
POST /api/v1/ask HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer xxxxx
```

Body：

```
{
  "question": "バックアップの保存期間は？"
}
```

という形です。

---

## 36. HTTP Response全体のイメージ

Serverからは、

```
HTTP/1.1 200 OK
Content-Type: application/json
```

Body：

```
{
  "answer": "30日間です。"
}
```

と返ります。

---

# 37. HTTP Status Code

HTTP Responseには、

処理結果を表すStatus Code

があります。

代表的なものは、

- 200
    
- 201
    
- 400
    
- 401
    
- 403
    
- 404
    
- 500
    

です。

---

## 38. 200 OK

正常に処理できた場合です。

例えば、

質問APIが正常に回答した

場合です。

---

## 39. 201 Created

新しいデータを作成できた場合に使います。

例えば、

新しい文書を登録した

場合です。

---

## 40. 400 Bad Request

Request内容がおかしい場合です。

例えば、

```
{
  "question": ""
}
```

のように、必須値が空の場合です。

---

## 41. 401 Unauthorized

認証できない場合です。

例えば、

- Tokenがない
    
- Tokenが期限切れ
    
- Tokenが無効
    

などです。

---

## 42. 403 Forbidden

認証はできているが、

権限がない

場合です。

例えば、

一般ユーザーが管理者APIを呼ぶ

場合です。

---

## 43. 404 Not Found

指定されたデータが存在しない場合です。

例えば、

存在しないDocument ID

を指定した場合です。

---

## 44. 500 Internal Server Error

Server内部でエラーが発生した場合です。

例えば、

- Python例外
    
- DB障害
    
- 外部API障害
    

などです。

---

# 45. Query Parameter

URLへ検索条件などを付けることができます。

例えば、

GET /documents?page=2&category=manual

です。

ここでは、

page = 2

category = manual

がQuery Parameterです。

---

## 46. Path Parameter

URLそのものに値を入れる場合です。

例えば、

GET /documents/123

なら、

123

がPath Parameterです。

通常、

特定のResourceを指定するときに使います。

---

## 47. Bodyとの使い分け

簡単にいうと、

Path Parameter  
→ どのデータか

Query Parameter  
→ どんな条件か

Body  
→ 送信する具体的なデータ

と考えると分かりやすいです。

---

# 48. HTTPS

HTTPの通信内容を暗号化する仕組みが、

HTTPS

です。

HTTP + TLS

という構成です。

APIでは、

- Token
    
- 個人情報
    
- 業務情報
    

などを扱うため、基本的にHTTPSを利用します。

---

## 49. HTTPは暗号化されない

通常のHTTPでは、

通信内容を暗号化しません。

そのため、

Authorization Header

や、

JSON Body

に重要情報を入れる場合はHTTPSが重要です。

---

# 50. REST APIとの関係

REST APIでは、

HTTP Method

と、

URL

を組み合わせてResourceを操作します。

例えば、

GET /documents  
→ 一覧取得

GET /documents/123  
→ 1件取得

POST /documents  
→ 新規作成

DELETE /documents/123  
→ 削除

という形です。

---

# 51. PythonでHTTP Requestを送る

Pythonでは、

requests

などのライブラリを使えます。

例えば、

```
import requests

response = requests.post(
    "https://example.com/api/v1/ask",
    json={
        "question": "バックアップの保存期間は？"
    },
)

print(response.status_code)
print(response.json())
```

です。

---

## 52. json=を使う意味

requestsで、

```
json={
    "question": "..."
}
```

とすると、

PythonのdictをJSONへ変換して送ってくれます。

さらに、

Content-Type: application/json

も適切に設定されます。

---

## 53. Headerを付ける

例えばToken認証なら、

```
headers = {
    "Authorization": "Bearer xxxxx"
}

response = requests.get(
    "https://example.com/api/v1/documents",
    headers=headers,
)
```

のようにします。

---

## 54. Response JSON

ServerからJSONが返ってきた場合、

```
data = response.json()

answer = data["answer"]
```

のようにPythonのdictとして利用できます。

---

# 55. JSONでよくある間違い

### Keyをダブルクォートで囲まない

誤り：

```
{
  name: "Taro"
}
```

正しい：

```
{
  "name": "Taro"
}
```

---

## 56. シングルクォート

JSONでは基本的に、

ダブルクォート

を使用します。

Python dictでは、

```
{
    'name': 'Taro'
}
```

でも動きますが、

これはJSONではなくPythonのdictです。

---

## 57. 最後のカンマ

JSONでは最後の要素に余分なカンマを付けると無効になることがあります。

誤り：

```
{
  "name": "Taro",
}
```

正しい：

```
{
  "name": "Taro"
}
```

---

## 58. PythonのTrueとJSONのtrue

Python：

```
True
False
None
```

JSON：

```
true
false
null
```

です。

似ていますが、大文字小文字が違います。

# 59. RAGでのHTTPとJSON

RAGシステムでは、例えば以下の場所でHTTPとJSONが使われます。

- Web画面 → RAG API
    
- RAG API → Embedding API
    
- RAG API → Search API
    
- RAG API → LLM API
    

つまりRAGでは、

**外部サービスとの接続部分でHTTP + JSONを頻繁に使う**

ことになります。

---

## 60. RAG APIの流れ

例えば、

ユーザー  
→ Web画面

Web画面  
→ HTTP POST

JSON：

```
{
  "question": "バックアップは何日保存しますか？"
}
```

RAG API  
→ Search  
→ LLM

Response：

```
{
  "answer": "30日間保存します。",
  "sources": [
    {
      "document": "DOC001",
      "page": 12
    }
  ]
}
```

という流れです。

---

## 61. 一言で理解する

HTTPは、

**「システム同士が通信するためのルール」**

です。

JSONは、

**「その通信で渡すデータの書き方」**

です。

APIでは、

**HTTPで通信して、JSONでデータをやり取りする**

という組み合わせが非常によく使われます。

覚え方としては、

**HTTP = 運び方**

**JSON = 荷物の中身の形式**

と考えると分かりやすいです。
