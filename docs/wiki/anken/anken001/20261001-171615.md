## 1. Managed Identityとは

Managed Identityは、

**Azure上のアプリケーションやリソースに、Azureが管理するIdentityを持たせる仕組み**

です。

主な目的は、

**Client SecretやAPI Keyをアプリ側で管理せずに、他のAzureサービスへ安全にアクセスすること**

です。

例えばRAGでは、

RAG API  
→ Azure AI Search

RAG API  
→ Azure OpenAI

Worker  
→ Blob Storage

RAG API  
→ Key Vault

などのアクセスに利用できます。

---

## 2. なぜ使うのか

通常、アプリから別サービスへアクセスする場合、

- API Key
    
- Client Secret
    
- Password
    

などの秘密情報が必要になることがあります。

秘密情報を持つと、

- 漏えい対策
    
- 保存場所
    
- Rotation
    
- 更新作業
    

が必要になります。

Managed Identityでは、認証に必要なCredentialをAzure側が管理するため、

**アプリケーションからSecretを減らせる**

ことが大きなメリットです。

---

## 3. 基本的な流れ

例えばRAG APIからAzure AI Searchへアクセスする場合、

RAG API  
→ Managed Identityを利用  
→ Entra IDからAccess Token取得  
→ Azure AI SearchへToken送信  
→ RBACで権限確認  
→ アクセス許可

という流れになります。

重要なのは、

**Managed Identity = 誰なのか**

を表し、

**RBAC = 何をしてよいか**

を決めることです。

---

## 4. System-assigned Managed Identity

Azure ResourceそのものにIdentityを付与する方式です。

例えば、

RAG App Service  
→ System-assigned Managed Identity

とします。

特徴は、

- Resource専用のIdentity
    
- 設定がシンプル
    
- Resource削除時にIdentityも削除される
    

ことです。

1つのアプリ専用Identityとして使う場合に分かりやすい方式です。

---

## 5. User-assigned Managed Identity

Identityを独立したAzure Resourceとして作成する方式です。

例えば、

RAG API  
RAG Worker  
Batch Function

から同じManaged Identityを利用できます。

特徴は、

- 複数Resourceで共有可能
    
- IdentityとアプリのLifecycleを分離できる
    
- Resourceを削除してもIdentityを残せる
    

ことです。

---

## 6. System-assignedとUser-assignedの違い

|項目|System-assigned|User-assigned|
|---|---|---|
|Identity|Resource専用|独立Resource|
|複数Resourceで共有|基本しない|可能|
|管理|シンプル|柔軟|
|Resource削除時|Identityも削除|Identityは残る|

単純な構成ならSystem-assigned、

複数サービスで共有したい場合はUser-assigned

と考えると分かりやすいです。

---

## 7. RBACとの関係

Managed Identityを作っただけでは、Azureサービスへアクセスできません。

そのIdentityに対して、

**必要なRoleを割り当てる**

必要があります。

例えば、

RAG Worker  
→ Blob読み取り権限

RAG API  
→ Azure AI Search検索権限

のように設定します。

この操作を、

Role Assignment

と呼びます。

---

## 8. 最小権限

Roleは必要最小限にします。

例えば、

BlobからPDFを読むだけのWorker

に、

Storage全体の管理権限

を与える必要はありません。

必要な操作だけ許可する、

Least Privilege

最小権限

が基本です。

---

## 9. RAGでの利用例

### Azure AI Search

RAG API  
→ Managed Identity  
→ Azure AI Search

検索に必要なRoleだけ付与します。

### Azure OpenAI

RAG API  
→ Managed Identity  
→ Azure OpenAI

Entra ID認証に対応した構成なら、API Keyを使わずアクセスできます。

### Blob Storage

Worker  
→ Managed Identity  
→ Blob Storage

文書原本の読み取りなどに使えます。

### Key Vault

RAG API  
→ Managed Identity  
→ Key Vault

必要なSecretだけ取得できるようにします。

---

## 10. Pythonでの利用イメージ

Azure SDKでは、

DefaultAzureCredential

を使うことがあります。

```
from azure.identity import DefaultAzureCredential

credential = DefaultAzureCredential()
```

Azure上ではManaged Identityを利用し、

ローカル開発ではAzure CLIなど別のCredentialを利用できます。

そのため、

開発環境と本番環境でコードを大きく変えずに認証できます。

---

## 11. ローカル開発との違い

ローカルPCには、通常Managed Identityはありません。

そのため、

ローカル  
→ Azure CLI Loginなど

Azure本番  
→ Managed Identity

という使い分けになります。

DefaultAzureCredentialを使うと、この切り替えをしやすくできます。

---

## 12. Key Vaultとの違い

Managed IdentityとKey Vaultは役割が違います。

### Managed Identity

**アプリが誰なのかを証明する**

### Key Vault

**Secretや暗号鍵を保存する**

例えば、

Managed IdentityでKey Vaultへアクセスし、

必要なSecretを取得する

という組み合わせができます。

ただし、AzureサービスへManaged Identityで直接アクセスできるなら、

**そもそもAPI KeyをKey Vaultへ保存しなくてよい**

場合もあります。

---

## 13. Client Secret方式との違い

### Client Secret

アプリが秘密情報を保持します。

そのため、

- 保存
    
- Rotation
    
- 漏えい対策
    

が必要です。

### Managed Identity

AzureがCredentialを管理します。

そのため、

- Secretをコードへ書かない
    
- Rotationを自分で管理しない
    
- Azure RBACと直接連携できる
    

というメリットがあります。

---

## 14. ユーザー認証との違い

Managed Identityは、

**人間のログイン用ではありません。**

例えば、

ユーザー  
→ OpenID Connect  
→ Entra ID Login

は人間の認証です。

一方、

RAG API  
→ Managed Identity  
→ Azure AI Search

はアプリケーション自身の認証です。

つまり、

User Identity  
= 人

Managed Identity  
= アプリ

と整理すると分かりやすいです。

---

## 15. エラー時に確認すること

Managed IdentityでAzureサービスへアクセスできない場合は、

1. Managed Identityが有効か
    
2. 正しいIdentityを使用しているか
    
3. 必要なRole Assignmentがあるか
    
4. Roleを付けたScopeが正しいか
    
5. 対象サービスがEntra ID認証に対応しているか
    

を確認します。

特に、

Identityは存在するがRoleがない

場合は、

403 Forbidden

になることがあります。

---

## 16. RAG全体での位置

RAGのAzure構成では、

User  
→ Entra ID Login  
→ RAG API

RAG API  
→ Managed Identity  
→ Azure AI Search

RAG API  
→ Managed Identity  
→ Azure OpenAI

Worker  
→ Managed Identity  
→ Blob Storage

という形で利用できます。

Managed Identityは、

検索や生成を担当する機能ではなく、

**Azureサービス同士を安全につなぐための認証手段**

です。

---

## 17. 一言で理解する

Managed Identityとは、

**「Azure上のアプリにAzure管理のIDを持たせ、Secretなしで他のAzureサービスへアクセスしやすくする仕組み」**

です。

覚えておくポイントは、

**Managed Identity = アプリのIdentity**

**RBAC = そのアプリが何をしてよいか**

です。

RAGでは、

**RAG APIやWorkerからAzure OpenAI・Azure AI Search・Blob Storage・Key Vaultへ安全に接続するために使う**

と理解すれば十分です。
