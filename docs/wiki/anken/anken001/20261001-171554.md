## 1. async / awaitとは

async / await は、

**Pythonで非同期処理を書くための仕組み**

です。

簡単にいうと、

**時間のかかる処理を待っている間に、別の処理を進められるようにする**

ために使います。

特に、

- API通信
    
- DBアクセス
    
- ファイルI/O
    
- LLM API
    
- Embedding API
    
- Search API
    

など、

「結果が返ってくるまで待つ処理」

と相性が良いです。

---

## 2. 同期処理との違い

通常のPython処理は、基本的に上から順番に実行します。

例えば、

処理A  
→ 完了するまで待つ  
→ 処理B  
→ 完了するまで待つ  
→ 処理C

という流れです。

これを同期処理と考えます。

---

## 3. 同期処理の例

例えば外部APIを2回呼ぶとします。

```
result_a = call_api_a()
result_b = call_api_b()
```

API Aに3秒、

API Bに3秒

かかる場合、

合計で約6秒

かかる可能性があります。

Aが終わるまで、Bは開始しません。

---

## 4. 非同期処理の考え方

非同期処理では、

API Aを待っている間にAPI Bも進める

ことができます。

イメージとしては、

API A開始  
＋  
API B開始  
→ 両方の完了を待つ

です。

両方がそれぞれ3秒なら、

約3秒程度で終わる可能性があります。

---

## 5. async

関数の前に、

async

を付けると、

非同期関数

として定義できます。

例えば、

```
async def fetch_data():
    pass
```

です。

このような関数を、

Coroutine

と呼ぶことがあります。

---

## 6. await

await は、

**非同期処理の完了を待つ**

ために使います。

例えば、

```
result = await fetch_data()
```

です。

ただ待つだけではなく、

その待ち時間中に、他の非同期処理へ実行を譲れる

というのが重要です。

---

## 7. async と await の基本

基本形は以下です。

```
async def get_data():
    result = await call_api()
    return result
```

つまり、

async  
→ 非同期関数を定義する

await  
→ 非同期処理の結果を待つ

という役割です。

---

## 8. await はどこでも使えるわけではない

await は基本的に、

async def の中

で使います。

例えば、

```
async def main():
    result = await fetch_data()
```

のようにします。

通常の def の中では、そのまま await は使えません。

---

## 9. Event Loop

Pythonの非同期処理では、

Event Loop

という仕組みが使われます。

Event Loopは、

**今どの処理を進められるかを管理する司令塔**

のようなものです。

例えば、

API A  
→ 応答待ち

API B  
→ 実行可能

なら、

API Aを待っている間にAPI Bを進めます。

---

## 10. asyncio

Python標準ライブラリには、

asyncio

があります。

async / await を使った非同期処理を管理するためのライブラリです。

例えば、

```
import asyncio
```

として使います。

---

## 11. 非同期関数を実行する

例えば、

```
import asyncio


async def main():
    print("start")
    await asyncio.sleep(1)
    print("end")


asyncio.run(main())
```

です。

asyncio.run() がEvent Loopを開始して、

main()

を実行します。

---

## 12. asyncio.sleep

非同期処理の学習では、

asyncio.sleep()

がよく使われます。

例えば、

```
await asyncio.sleep(3)
```

です。

これは3秒待ちますが、

time.sleep(3)

とは違い、

その間に別の非同期処理を実行できます。

---

## 13. time.sleepとの違い

### time.sleep

```
import time

time.sleep(3)
```

その処理全体を止めます。

### asyncio.sleep

```
await asyncio.sleep(3)
```

自分は待ちますが、

Event Loopは別の処理を進められます。

---

## 14. 並行処理

async / await を使う大きな理由の1つが、

複数の処理を並行して進める

ことです。

例えば、

- Search API
    
- User API
    
- Document API
    

を同時に呼び出す場合です。

---

## 15. asyncio.gather

複数の非同期処理をまとめて実行する場合、

asyncio.gather()

を使えます。

例えば、

```
import asyncio


async def main():
    result_a, result_b = await asyncio.gather(
        call_api_a(),
        call_api_b(),
    )
```

です。

API AとAPI Bを並行して進めます。

---

## 16. RAGでの利用例

RAGでは、

- Keyword Search
    
- Vector Search
    

を並行して実行できます。

例えば、

```
keyword_results, vector_results = await asyncio.gather(
    keyword_search(question),
    vector_search(question),
)
```

です。

Hybrid Searchと相性が良い使い方です。

---

## 17. LLM APIとの相性

LLM APIは、

Request送信  
→ Server処理  
→ Response待ち

という待ち時間があります。

そのため、

async / await

と相性が良いです。

例えば、

```
answer = await llm.generate(prompt)
```

のようにします。

---

## 18. Embedding APIとの相性

Embedding処理も外部APIなら、

待ち時間

が発生します。

複数ChunkをEmbeddingする場合、

並行化できる場合があります。

例えば、

```
vectors = await asyncio.gather(
    embed(chunk1),
    embed(chunk2),
    embed(chunk3),
)
```

です。

---

## 19. ただし大量並列は危険

1000件のAPIを一気に投げると、

- Rate Limit
    
- 接続数超過
    
- メモリ増加
    
- API料金増加
    

などの問題が起きます。

そのため、並行数を制限することがあります。

---

## 20. Semaphore

同時実行数を制限するために、

asyncio.Semaphore

を使えます。

例えば、

```
semaphore = asyncio.Semaphore(5)
```

とすると、

最大5処理まで

に制限できます。

---

## 21. Semaphoreの例

```
import asyncio


semaphore = asyncio.Semaphore(5)


async def embed_with_limit(text):
    async with semaphore:
        return await embed(text)
```

これによって、

大量のEmbedding処理を安全に並行実行できます。

---

## 22. CPU処理には向いていない

async / await は、

何でも高速化できる仕組みではありません。

特に、

- 大量計算
    
- 画像処理
    
- 圧縮処理
    
- 重い機械学習計算
    

のようなCPUをずっと使う処理には向いていません。

async / await が得意なのは、

**待ち時間が多い処理**

です。

---

## 23. I/O Bound

async / await が得意な処理を、

I/O Bound

と呼びます。

例えば、

- HTTP通信
    
- DBアクセス
    
- ファイル読み書き
    
- 外部API通信
    

です。

RAGは外部APIやSearchとの通信が多いため、I/O Boundな処理が多くなります。

---

## 24. CPU Bound

CPU計算が中心の処理を、

CPU Bound

と呼びます。

例えば、

- 大規模な画像変換
    
- 数値計算
    
- ローカルAI推論
    

などです。

この場合は、

- multiprocessing
    
- ProcessPool
    
- GPU
    

など別の仕組みを検討します。

---

## 25. 並行と並列の違い

少し似ています。

### 並行

複数の処理を切り替えながら進める。

async / await は主にこちらです。

### 並列

複数のCPUなどで本当に同時実行する。

multiprocessingなどがこちらです。

---

## 26. FastAPIとasync

FastAPIでは、

async def

でAPI Endpointを定義できます。

例えば、

```
@app.post("/ask")
async def ask(request: AskRequest):
    answer = await rag_service.ask(
        request.question
    )

    return {
        "answer": answer
    }
```

です。

---

## 27. FastAPIでasyncを使う理由

RAG APIでは、

1つのRequest中に、

- Search API
    
- Embedding API
    
- LLM API
    

などを呼びます。

これらの待ち時間中に、

別ユーザーのRequest

を処理できるようになります。

そのためWeb APIと非同期処理は相性が良いです。

---

## 28. 同期ライブラリをawaitしても意味はない

例えば、

requests

は基本的に同期ライブラリです。

```
requests.get(...)
```

をasync関数の中で実行しても、

その通信中は処理が止まります。

---

## 29. 非同期HTTPライブラリ

非同期HTTP通信には、

httpx

や

aiohttp

などがあります。

例えば、

```
import httpx


async with httpx.AsyncClient() as client:
    response = await client.get(
        "https://example.com"
    )
```

です。

---

## 30. 同期処理と非同期処理を混ぜる場合

実際のアプリでは、

同期ライブラリ

と

非同期ライブラリ

が混在することがあります。

重い同期処理をそのままasync関数内で実行すると、

Event Loopを止める

可能性があります。

そのため注意が必要です。

---

## 31. awaitし忘れ

よくあるミスです。

例えば、

```
result = fetch_data()
```

と書いてしまうと、

結果ではなくCoroutine Object

が返る場合があります。

正しくは、

```
result = await fetch_data()
```

です。

---

## 32. Coroutineとは

async def で作った関数を呼ぶと、

すぐに結果が返るのではなく、

Coroutine Object

が作られます。

例えば、

```
async def hello():
    return "hello"
```

に対して、

```
result = hello()
```

だけでは、まだ処理は完了していません。

awaitが必要です。

---

## 33. Task

CoroutineをEvent Loop上で実行する単位として、

Task

があります。

例えば、

```
task = asyncio.create_task(
    fetch_data()
)
```

です。

Taskにすると、他の処理と並行して実行できます。

---

## 34. create_task

例えば、

```
task_a = asyncio.create_task(
    call_api_a()
)

task_b = asyncio.create_task(
    call_api_b()
)

result_a = await task_a
result_b = await task_b
```

とできます。

gatherと似た用途です。

---

## 35. Timeout

非同期処理でも、

外部APIが返ってこない

可能性があります。

そのためTimeoutを設定します。

例えば、

```
result = await asyncio.wait_for(
    call_api(),
    timeout=30,
)
```

です。

30秒を超えたらTimeoutになります。

---

## 36. Retryとの組み合わせ

RAGでは、

async  
＋  
Timeout  
＋  
Retry

を組み合わせることがあります。

例えば、

LLM API  
→ Timeout  
→ 一時エラー  
→ Retry

という流れです。

---

## 37. 例外処理

非同期処理でも、

try / except

を使います。

```
try:
    result = await call_api()

except Exception as e:
    logger.error(e)
```

です。

---

## 38. gatherと例外

asyncio.gatherで複数処理をまとめている場合、

1つの処理が失敗

すると全体に影響することがあります。

用途によって、

```
await asyncio.gather(
    task_a(),
    task_b(),
    return_exceptions=True,
)
```

なども使います。

## 40. 並行化しにくい処理

前の結果が必要な処理は、

順番に実行

する必要があります。

例えば、

質問  
→ Embedding  
→ Vector Search

の場合、

Embedding結果がないとVector Searchできません。

そのため、この2つはそのまま並行実行できません。

---

## 41. RAGの処理依存関係

例えば、

Question  
→ Embedding  
→ Vector Search

と、

Question  
→ Keyword Search

があります。

Keyword SearchはEmbeddingを待つ必要がありません。

そのため、

Keyword Search

と、

Embedding → Vector Search

の流れ

をある程度並行化できます。

## 42. 非同期RAGのイメージ

例えば、

```
async def retrieve(question):

    keyword_task = asyncio.create_task(
        keyword_search(question)
    )

    query_vector = await embed(question)

    vector_task = asyncio.create_task(
        vector_search(query_vector)
    )

    keyword_results = await keyword_task
    vector_results = await vector_task

    return merge_results(
        keyword_results,
        vector_results,
    )
```

のような考え方です。

---

## 43. レスポンスタイム改善

非同期処理を使うことで、

外部APIの待ち時間を重ねられる

ため、全体レスポンスタイムを短縮できる場合があります。

特に、

複数の独立したAPI呼び出し

がある場合に効果があります。

---

## 44. 非同期にすれば必ず速いわけではない

例えば、

処理A  
→ 処理B  
→ 処理C

がすべて前の結果に依存している場合、

asyncにしても大きな高速化はできません。

重要なのは、

**独立した待ち処理が複数あるか**

です。

---

## 45. async / awaitのコードは少し複雑になる

非同期処理を使うと、

- awaitし忘れ
    
- Timeout
    
- Task管理
    
- 例外処理
    
- 並行数制限
    

などを考える必要があります。

そのため、

単純なスクリプト

なら同期処理のほうが分かりやすい場合もあります。

---

## 46. いつ使うべきか

RAGでは特に、

- Web API化する
    
- 複数外部APIを使う
    
- 同時ユーザーがいる
    
- Keyword / Vector Searchを並行したい
    

場合にasync / awaitが役立ちます。

---

## 47. いつ無理に使わなくてよいか

例えば、

ローカルで、

1ファイル  
→ Chunk  
→ Embedding  
→ 検索

を試すだけの学習用スクリプトなら、

最初は同期処理でも問題ありません。

仕組みを理解してから非同期化したほうが分かりやすいです。

---

## 48. 一言で理解する

async / awaitとは、

**「APIやDBなどの待ち時間中に、別の処理を進めるためのPythonの仕組み」**

です。

async  
＝ 非同期関数を作る

await  
＝ 非同期処理の完了を待つ

です。

RAGでは、

- LLM API
    
- Embedding API
    
- Keyword Search
    
- Vector Search
    

など、外部通信が多いため非常に相性が良いです。

覚え方としては、

**async / await = 待ち時間を無駄にしない仕組み**

で十分です。
