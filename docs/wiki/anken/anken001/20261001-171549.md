## 1. Tokenとは

Token（トークン）は、

**LLMが文章を読み書きするときに使う処理単位**

です。

人間は文章を「文字」や「単語」として見ますが、LLMは文章をTokenに分割して処理します。

例えば、

「今日は晴れです」

という文章も、LLM内部では複数のTokenに分割されます。

---

## 2. Tokenは文字数と同じではない

Tokenは、

1文字 = 1 Token

ではありません。

また、

1単語 = 1 Token

とも限りません。

文章はモデルごとのTokenizerによって分割されます。

例えば英語では、

computer

が1 Tokenになる場合もあれば、

長い単語が複数Tokenに分かれる場合もあります。

日本語も、

文字  
単語  
文章の一部

などに分割されます。

そのため、

**文字数だけから正確なToken数を判断することはできません。**

---

## 3. Tokenizer

文章をTokenへ分割する仕組みを、

Tokenizer

と呼びます。

流れとしては、

文章  
→ Tokenizer  
→ Token列  
→ LLM

となります。

LLMやEmbeddingモデルによってTokenizerが異なる場合があります。

---

## 4. Input TokenとOutput Token

LLMではTokenを大きく、

- Input Token
    
- Output Token
    

に分けて考えます。

### Input Token

LLMへ送る情報です。

例えば、

- System Prompt
    
- Context
    
- ユーザー質問
    
- 会話履歴
    

などです。

### Output Token

LLMが生成した回答です。

つまり、

入力文章  
→ Input Token

生成された回答  
→ Output Token

となります。

---

## 5. RAGとToken

RAGでは、LLMへ以下のような情報を送ります。

System Prompt  
＋  
検索したContext  
＋  
会話履歴  
＋  
ユーザー質問

これらすべてがInput Tokenになります。

例えば検索結果を大量にContextへ入れると、

Token数も増えます。

---

## 6. Context Window

LLMが一度に処理できるToken数には上限があります。

これを、

Context Window

と呼びます。

Context Windowには、

- System Prompt
    
- 会話履歴
    
- RAGのContext
    
- ユーザー質問
    

などが含まれます。

さらに、モデルやAPIの仕様によっては生成する回答分も考慮する必要があります。

---

## 7. ContextとContext Windowの違い

名前が似ているので注意します。

### Context

RAGで検索した回答根拠。

### Context Window

LLMが一度に扱えるToken量の範囲。

つまり、

Contextは「情報そのもの」

Context Windowは「入れられる容量」

と考えると分かりやすいです。

---

## 8. Token Budget

限られたContext Windowをどの情報に使うか考えることを、

Token Budget

と考えます。

例えば、

System Prompt  
1,000 Token

会話履歴  
2,000 Token

RAG Context  
8,000 Token

ユーザー質問  
200 Token

回答生成用  
2,000 Token

のように配分します。

---

## 9. ChunkとToken

RAGではChunk SizeをToken単位で決める場合があります。

例えば、

1 Chunk = 500 Token

とします。

その場合、

Top-K = 5

なら、

単純計算では最大約2,500 Token分のChunkを取得することになります。

実際には、

- Metadata
    
- Prompt
    
- 区切り文字
    

などもTokenを使用します。

---

## 10. Top-Kとの関係

例えば、

1 Chunk = 500 Token

の場合、

Top-K = 5  
→ 約2,500 Token

Top-K = 20  
→ 約10,000 Token

となります。

Top-Kを増やすほど、

LLMへ渡す情報量

も増えやすくなります。

そのため、

**Chunk SizeとTop-Kはセットで考える**

ことが重要です。

---

## 11. PromptとToken

PromptもTokenを消費します。

例えば、

- 回答ルール
    
- 出力形式
    
- Few-shot例
    
- 長いSystem Prompt
    

などを増やすほどInput Tokenが増えます。

そのため、必要以上に長いPromptは、

- コスト増加
    
- 処理量増加
    
- Contextに使える容量減少
    

につながります。

---

## 12. 会話履歴とToken

チャット型RAGでは、過去の会話もTokenを使用します。

会話が長くなるほど、

ユーザー  
→ Assistant  
→ ユーザー  
→ Assistant

という履歴が増えていきます。

そのため、

- 古い会話を削る
    
- 要約する
    
- 関係する履歴だけ使う
    

などの処理を行うことがあります。

---

## 13. Tokenが多すぎる場合

Context Windowを超えると、そのままではLLMへ送信できません。

そのため、

- Top-Kを減らす
    
- Chunkを小さくする
    
- Context Compression
    
- 会話履歴を要約する
    
- 不要なPromptを削る
    

などでToken数を減らします。

---

## 14. Tokenが少なすぎても問題

Tokenを減らすことだけを考えると、

必要な情報まで削除

する可能性があります。

例えば、

「10万円以上の場合」

という条件部分を削ってしまうと、回答内容が変わります。

そのため、

**Token削減と情報量のバランス**

が重要です。

---

## 15. Tokenと料金

多くのLLM APIでは、

処理したToken数

が料金計算に関係します。

一般的には、

Input Token  
Output Token

それぞれに料金設定があります。

そのためRAGでは、

検索結果を大量にLLMへ渡す

と利用料金も増えやすくなります。

---

## 16. EmbeddingとToken

Embedding APIでも文章をTokenとして処理します。

例えば大量のPDFを、

Chunk  
→ Embedding

すると、各ChunkのToken量に応じて処理量が増えます。

そのため文書取り込み時にもTokenを意識することがあります。

---

## 17. Tokenとレスポンスタイム

Token数が増えると、

- 入力処理
    
- 推論
    
- 出力生成
    

に時間がかかる場合があります。

特に大量のContextを毎回渡すと、回答速度に影響することがあります。

---

## 18. Output Token

回答の長さもToken数で制御されることがあります。

例えば、

最大2,000 Output Token

のように上限を設定します。

長すぎる回答が不要なRAGでは、Output Tokenを適切に制限することで、

- コスト
    
- 応答時間
    
- 不要な長文
    

を抑えられます。

---

## 19. Token数はどう確認するのか

正確なToken数を確認したい場合は、

**利用するモデルに対応したTokenizer**

を使って計算します。

単純な文字数換算は目安にはなりますが、正確ではありません。

特に日本語では、

「1000文字だから1000 Token」

とは限りません。

---

## 20. Token設計で見るポイント

RAGでは主に、

- Chunk Size
    
- Top-K
    
- Context量
    
- Prompt量
    
- Conversation History
    
- Output Token
    

を確認します。

これらを合わせたToken量が、

LLMのContext Window

に収まるように設計します。

---

## 21. RAG全体での位置

Tokenは特定の1処理ではなく、RAG全体に関係します。

Document  
→ Chunk  
→ Embedding

質問時：

Question  
→ Search  
→ Context  
→ Prompt  
→ LLM  
→ Answer

この中で、

Chunk  
Embedding  
Context  
Prompt  
Answer

など、さまざまな場所でTokenが関係します。

---

## 22. 一言で理解する

Tokenとは、

**「LLMが文章を処理するために分割した単位」**

です。

RAGでは、

**Contextを増やすほどTokenも増えやすい**

ため、

Chunk Size  
×  
Top-K  
＋  
Prompt  
＋  
会話履歴

を意識することが重要です。

覚え方としては、

**Token = LLMが文章を読むための単位**

で十分です。
