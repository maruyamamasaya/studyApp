# 1. 概要

Keyword Search（キーワード検索）は、入力した語句と文書中の語句の一致を使う検索です。検索の前に文章を単語などへ分ける処理を行うことが多く、この処理を解析器（Analyzer）が担当します。

# 2. 何のために使うか

製品番号、規程名、エラーコードなど、文字列自体が重要な質問に使います。ベクトル検索では似た意味に埋もれやすい識別子を、明示的に探す手段になります。

# 3. 仕組み

検索索引は、どの語がどの文書に出るかを整理した転置索引を持ちます。BM25という代表的な順位付け方式は、語の出現、珍しさ、文書長などを考慮します。完全一致、語句一致、全文検索は同じ動作ではないため、クエリ形式を確認します。

# 4. 具体例

Te社の学習用想定例で、エラーコード「AUTH-001」を含む手順書を探します。ハイフンで単語が分かれると期待どおりに一致しない場合があるため、全文用の本文と、識別子を保持する専用フィールドを分ける設計を検討します。

# 5. 実装・設定時のポイント

- 日本語の解析器、検索対象フィールド、同義語を確認します。
- 大文字小文字、全角半角、ハイフンを評価します。
- ユーザー入力を検索構文として直接解釈するか、安全な単純検索にするか決めます。
- タイトルや製品番号の重み付けは評価結果を見て調整します。

# 6. 注意点

同じ語が多いだけの文書が上位に来ることがあります。語句が一致していても古い版や適用外の規程である可能性があります。表記ゆれを補う同義語設定が、意図しない一致を増やしていないか確認します。

# 7. Te社RAG基盤で確認するポイント

searchableフィールド、Analyzer、search_fields、query_type、同義語マップを確認します。コードが生成する検索文字列を機密情報を除いた形で検証し、設計書の検索仕様と対応付けます。番号検索と自然言語質問を分けてテストします。
