# 1. 概要

Embedding（埋め込み）は、文章などを数値の並びであるベクトルへ変換する処理です。意味が近い文章を、ベクトル空間で近くなるように表現します。元の文章そのものを保存したり、暗号化したりする技術ではありません。

# 2. 何のために使うか

質問と文書で言い回しが違っていても、意味の近い根拠を探すために使います。「休暇申請」と「休みを取りたい」のような表現の違いを検索で扱いやすくします。

# 3. 仕組み

取り込み時にChunkをEmbeddingモデルへ送ってベクトルを保存します。検索時には質問を互換性のある同じモデル・設定で変換し、ベクトル間の距離や類似度を比較します。次元数はベクトルの数値の個数で、検索フィールドの定義と一致する必要があります。

# 4. 具体例

Te社の想定例では、規程の各Chunkをベクトル化し、「育児で勤務時間を短くしたい」という質問から、短時間勤務制度の説明を探します。名称の完全一致が必要な検索ではキーワード検索も併用します。

# 5. 実装・設定時のポイント

- モデル名、デプロイ名、次元数、入力制限を記録します。
- 本文用と質問用のモデル互換性を確認します。
- 空文字や長すぎる入力を事前に検出します。
- モデル変更時には索引を再生成し、新旧ベクトルを混在させない計画を作ります。

# 6. 注意点

類似度の高さは事実の正しさを示しません。否定文や数字の違い、古い規程も近くなる場合があります。ベクトルも元データの情報を反映するため、公開してよい匿名データだと扱わないようにします。

# 7. Te社RAG基盤で確認するポイント

Embedding呼び出し箇所、利用デプロイ、登録ベクトルの長さ、検索時の変換処理を確認します。SDKで返る使用量、バッチの部分失敗、429応答の処理を調べます。モデル切り替えの手順と索引の世代管理を設計書へ対応付けます。
