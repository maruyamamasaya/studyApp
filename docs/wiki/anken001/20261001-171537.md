# 1. 概要

PDF解析は、表示用のPDFから本文、見出し、表、ページ位置などを取り出す処理です。文字データを含むPDFと、紙を撮影した画像中心のPDFでは、必要な抽出方法が異なります。

# 2. 何のために使うか

LLMや検索エンジンが利用できるテキストを作り、回答の出典ページを保持します。段組みや表の対応関係を保つことは、検索結果の意味を保つことにもつながります。

# 3. 仕組み

PDFには文字の位置が保存されていても、自然な読順が保証されない場合があります。抽出器が座標を解釈して文章を並べます。文字を抽出できないページではOCRを使います。Layout解析は本文に加えて表や段落などの構造を扱います。[Layoutモデルの公式説明](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/layout)

# 4. 具体例

Te社の旅費表を想定すると、金額だけを抽出して都市名との対応を失うと誤回答になります。「都市：大阪、宿泊上限：仮の金額」のように行と列の関係を保ってテキスト化し、元の表位置も保持します。

# 5. 実装・設定時のポイント

- 日本語、縦書き、段組み、結合セル、脚注を含むサンプルで比較します。
- ページ番号はPDF内部の通し番号と紙面の表示番号を区別します。
- 原本のハッシュ、抽出器の版、抽出日時を保存します。
- 空文字でも成功と扱わず、文字量や欠落ページを確認します。

# 6. 注意点

ヘッダーやフッターの繰り返しが検索を汚すことがあります。一方、削りすぎると章名や重要な注意書きを失います。抽出結果を原本と見比べ、削除する規則を説明できるようにします。

# 7. Te社RAG基盤で確認するポイント

PDFパーサーのライブラリと版、OCRへの切り替え条件、表の保存形式、ページ属性の引き継ぎを確認します。設計書の対応形式と、現行コードが処理できる形式が一致するか調べます。元PDFへ戻れる出典情報も確認します。
