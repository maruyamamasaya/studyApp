# 1. 概要

JWT署名鍵は、JWTが信頼する発行者によって発行され、改ざんされていないことを確認するための鍵です。非対称署名では発行者が秘密鍵で署名し、APIは対応する公開鍵で検証します。

# 2. 何のために使うか

Entra IDのAccess TokenをRAG APIが安全に検証するために使います。APIがEntra IDの秘密鍵を受け取る必要はありません。

# 3. 仕組み

信頼するIssuerのDiscovery情報からJWKS（JSON Web Key Set：公開鍵の集合）の場所を取得します。Token Headerのkidに対応する鍵を選び、署名を検証します。署名鍵は更新されるため、公開鍵をキャッシュしつつ更新する設計が必要です。[鍵更新の公式説明](https://learn.microsoft.com/en-us/entra/identity-platform/signing-key-rollover)

# 4. 具体例

Te社APIが鍵更新後に未知のkidを受け取った場合、信頼する場所から公開鍵を更新して再確認します。更新できず検証が成立しないTokenを、署名なしで受け入れる回避は行いません。

# 5. 実装・設定時のポイント

- JWKS取得先を検証済みの設定に固定します。
- 未知kid時の再取得に回数制限と待機を設けます。
- 鍵キャッシュの期限と、更新障害時の動作を決めます。
- kidだけでなく、鍵用途やアルゴリズムの整合も確認します。

# 6. 注意点

Token Headerが示す任意URLへ鍵を取りに行くと、攻撃者の鍵や内部ネットワークへのアクセスを誘導される危険があります。既知の鍵を使える場合と未知の鍵が必要な場合を区別し、更新障害時の方針を明示します。

# 7. Te社RAG基盤で確認するポイント

JWKSクライアント、Discovery URL、Issuer固定、キャッシュ、鍵更新、取得Timeoutを確認します。鍵更新を模したテストと、取得不能時の拒否を調べます。アプリ独自JWTがある場合は、Entra ID署名鍵と独自鍵を別に管理します。
