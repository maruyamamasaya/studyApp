# 1. 概要

Metadata（メタデータ）は、本文に付ける文書ID、部署、版、日付、閲覧権限などの属性です。Metadata Filterは、その属性を条件に検索対象を絞る仕組みです。

# 2. 何のために使うか

最新版だけを検索したり、利用者に許可された文書だけを検索したりするために使います。業務的な絞り込みと、情報漏えいを防ぐ認可の両方に関わります。

# 3. 仕組み

Azure AI Searchではfilterableな非ベクトルフィールドへ条件を指定します。ベクトル検索ではpreFilterとpostFilterなどの適用方式があり、候補の取り方に影響します。[公式説明](https://learn.microsoft.com/en-us/azure/search/vector-search-filters)

権限条件は、検証済みの利用者情報からサーバー側で生成します。クライアントから送られた部署名だけを信用して条件を作ってはいけません。

# 4. 具体例

Te社の想定例で、総務向け文書と全社文書を検索対象にする場合、利用者の確定した権限に基づく条件を生成します。結果には許可されない本文を含めず、Context、引用、キャッシュにも同じ制約を適用します。

# 5. 実装・設定時のポイント

- 文書のACL（アクセス制御リスト）の取得元と更新手順を確認します。
- 任意文字列をOData式へ直接連結せず、型とエスケープを管理します。
- グループ情報が省略されるトークンの場合の権限取得を設計します。
- 権限情報が取得できない場合は、安全側で検索を拒否します。

# 6. 注意点

LLMへ渡してから画面だけで隠す方式では、機密情報の送信を防げません。フィルター変更がキャッシュへ反映されないと漏えいすることもあります。文書原本へ戻るダウンロードAPIにも認可が必要です。

# 7. Te社RAG基盤で確認するポイント

索引の権限フィールド、取り込み時の付与、検索時の条件生成を一続きに追います。キーワード・ベクトル・再検索の全経路で適用されるか確認します。部署を偽装するリクエストと権限変更後のリクエストをテストします。
