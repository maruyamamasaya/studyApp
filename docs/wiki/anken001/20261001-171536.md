> Te社向けの例は学習用の想定です。実際の採用サービス・設定・権限は、既存コードと正式資料で確認してください。

# 1. 概要

文書取り込みは、原本を取得し、検索に適したデータへ加工して登録する処理です。単なるファイルのアップロードではなく、原本の版、抽出品質、閲覧権限、登録状態を管理する仕事も含みます。

# 2. 何のために使うか

利用者が質問した時点で、正しい資料をすぐ検索できるようにします。取り込みを事前処理にすることで、PDF解析などの重い処理を質問APIから切り離せます。

# 3. 仕組み

文書IDと原本のハッシュ（内容から計算する識別値）を取得し、変更の有無を判定します。本文を抽出し、Chunkへ分割して各Chunkに文書ID、版、ページ、権限を付けます。Embeddingと一緒に登録し、各登録結果を確認してから公開済み状態にします。

冪等性は、同じ処理を再実行しても不要な重複や副作用が増えない性質です。文書ID・版・Chunk番号などから安定した登録キーを作ると再実行しやすくなります。

# 4. 具体例

Te社の規程第2版を取り込む想定では、第1版のChunkを放置せず、最新版だけを検索する切り替えや旧版削除を行います。本文が同じでも閲覧権限が変わった場合は、権限情報を更新します。

# 5. 実装・設定時のポイント

- ファイル形式、容量、ページ数、暗号化の可否を入口で検証します。
- 状態を受付・処理中・登録済み・失敗などに分けます。
- バッチ登録の部分失敗を個別に確認します。
- 原本削除時に索引、キャッシュ、抽出データも追跡して削除します。

# 6. 注意点

文書の取り込み途中で新旧版が混在することがあります。世代の切り替えや、公開フラグの更新手順を設計します。再試行でOCRやEmbeddingを毎回やり直すと、費用が増えるため中間結果を再利用できる単位を考えます。

# 7. Te社RAG基盤で確認するポイント

取り込みの起動方式が手動、定期実行、イベントのどれか確認します。索引キーの生成、更新・削除の実装、処理済み判定、権限属性の取得元を読みます。失敗文書一覧を運用担当者が確認し、安全に再処理できるかを検証します。
