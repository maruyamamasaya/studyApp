# 1. 概要

Application Insightsは、アプリの要求、依存先呼び出し、例外、分散トレースなどを観測するAzure Monitorの機能です。分散トレースは、複数の処理を同じ追跡情報で結び付ける仕組みです。[公式概要](https://learn.microsoft.com/en-us/azure/azure-monitor/app/app-insights-overview)

# 2. 何のために使うか

RAGの応答が遅い理由や、検索・生成のどちらで失敗したかを調べます。利用者の1要求から外部通信までを追えると、詳細設計書の処理フローも検証できます。

# 3. 仕組み

SDKやOpenTelemetryという観測データの標準的な仕組みで、処理の区間をSpanとして記録します。HTTP要求と依存先呼び出しの親子関係、所要時間、成否を集めます。保存先やテーブル形式は採用構成で確認します。

# 4. 具体例

Te社の想定例で質問APIが8秒なら、検索0.5秒、Context構築0.1秒、生成7秒などに分解して調べます。Embeddingを質問時に行うなら、その区間も個別に観測します。

# 5. 実装・設定時のポイント

- SDKの初期化と非同期処理への追跡情報の引き継ぎを確認します。
- 検索、再順位付け、生成、取り込みを区間として分けます。
- サンプリング（記録する割合）の影響を理解します。
- 本文、トークン、秘密、SAS付きURLを収集しないようにします。

# 6. 注意点

自動計測だけで業務上の段階が全部見えるとは限りません。サンプリングされたトレース件数をそのまま全件数と扱わないようにします。例外のmessageへ入力全文が含まれる場合もあるため、収集前に確認します。

# 7. Te社RAG基盤で確認するポイント

接続設定、初期化箇所、トレース属性、計測対象、サンプリング、Workspaceを確認します。1つの質問を追って各区間がつながるか調べます。ログやTraceの閲覧権限と保持期間も確認します。
