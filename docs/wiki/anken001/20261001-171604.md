# 1. 概要

Blob Storageは、PDFや画像などのファイルをオブジェクトとして保存するAzureのサービスです。Storage Accountの中にContainerがあり、その中へBlobを保存します。[公式概要](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction)

# 2. 何のために使うか

RAG文書の原本、抽出結果、中間生成物などを保存します。検索結果から原本を確認したり、取り込みを再実行したりするための土台になります。

# 3. 仕組み

アプリやWorkerがHTTPSとSDKでBlobを読み書きします。文書IDと保存先、版、ETag（更新を識別する値）などを対応付けます。索引には原本を特定する属性を持たせ、検索用本文とは別に原本を管理します。

# 4. 具体例

Te社の想定例で原本をraw、抽出本文をprocessedという別Containerへ保存します。利用者へ原本を返すAPIは再度文書権限を確認します。学習例のContainer名を実構成だと扱わないようにします。

# 5. 実装・設定時のポイント

- 匿名公開の設定とネットワーク到達範囲を確認します。
- Managed Identityによるデータ操作権限を設定します。
- Versioning、Soft Delete、バックアップ、保持期間を要件に合わせます。
- SASという期限・権限付きのアクセス情報を使う場合は、対象と期限を絞ります。

# 6. 注意点

Container名の非公開性はアクセス制御になりません。SAS付きURLは所持者が使える場合があるため、ログへ残さないようにします。原本を消しても索引やキャッシュに本文が残るため、削除処理を連動させます。

# 7. Te社RAG基盤で確認するポイント

Account、Container、Blob pathの生成、認証方式、ダウンロードAPIを確認します。原本IDとChunkの対応、更新検知、削除伝播を調べます。リソース管理用Roleだけで読めると決めつけず、データプレーンの割り当てを確認します。
