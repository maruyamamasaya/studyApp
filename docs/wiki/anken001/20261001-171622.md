# 1. 概要

この資料は、Te社の既存RAG基盤を読み解き、詳細設計書と実装の対応を確認するための調査ガイドです。保存先の既存案件メモではAzure上のPython基盤を調べる作業と整理されていますが、実ソースコード、Azure設定、正式設計資料は今回未確認です。

# 2. 何のために使うか

想定を確定事項として書かず、確認すべき対象、証跡、未解決事項を管理するために使います。既存提供資料とTe社で変更した部分の差分を説明できる状態を目指します。

# 3. 仕組み

調査は、正式テンプレートと対象環境の確定、リポジトリとデプロイの対応確認、API入口からの処理追跡、Azure接続と認可確認、異常系と運用確認の順で進めます。「資料にある」「コードにある」「実行環境で確認した」を分けて記録します。

# 4. 具体例

以下は確認表の例です。正式な設計書の項目数・納期は案件担当者へ確認し、この一覧をそのまま実仕様にはしません。

# 5. 実装・設定時のポイント

- 各設計項目に、ファイル・関数・設定名・テストを対応付けます。
- 設定の既定値、環境変数、Azure実値の優先関係を確認します。
- 提供版と現行版の差分はGit履歴などで確認します。
- 調査票へ確定、未確認、差分ありの状態と確認日を付けます。

# 6. 注意点

既存メモ中の「可能性がある」「と考えられる」は確定仕様ではありません。専用AIへ入力できる情報も正式規程を確認します。実装理由が不明な場合は、コードから挙動だけを記録し、理由は質問事項として残します。

# 7. Te社RAG基盤で確認するポイント

最初に正式納期、成果物の項目、レビュー担当、ソース修正の範囲を確認します。次に稼働コミットとデプロイ設定を特定し、正しい環境を対象にします。最後に権限拒否、根拠なし、外部障害、文書更新を代表ケースとして、設計・コード・実行結果の三者を照合します。
