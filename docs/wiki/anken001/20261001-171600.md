# 1. 概要

並列処理は、複数の仕事を同時に進める設計です。待機中に別の仕事を進める並行性と、複数のCPUなどで同時に実行する並列性を区別すると、Pythonコードの意図を理解しやすくなります。

# 2. 何のために使うか

取り込み速度や質問処理の応答時間を改善します。ただし、外部APIのレート制限やメモリー容量を超えないように制御する必要があります。

# 3. 仕組み

通信中心ならasyncio、同期の入出力ならスレッド、重いCPU処理ならプロセスなどを検討します。通常のCPythonではGILという実行制約がありますが、Pythonの版、ビルド、利用ライブラリで条件が変わります。選択は実際の処理時間で判断します。

# 4. 具体例

次のコードは非同期処理の同時数を3へ制限する学習用抜粋です。embedは別途実装する関数です。Te社の大量Embeddingを想定し、要求を無制限に一斉送信しない意図を示します。

~~~python
import asyncio

limit = asyncio.Semaphore(3)

async def embed_limited(text):
    async with limit:
        return await embed(text)
~~~

# 5. 実装・設定時のポイント

- 同時数に加え、1分当たりの要求数とToken量を制限します。
- 巨大なTask一覧を作らず、バッチやQueueで段階的に処理します。
- 部分失敗を仕事単位で記録します。
- 接続プール、メモリー、Worker台数を含めて負荷試験します。

# 6. 注意点

Semaphoreはアプリの各プロセス内だけで効く場合があります。台数が増えると全体の同時数も増えます。共有するクライアントのスレッド安全性を確認し、CPU処理をasyncにしただけで高速化したと判断しないようにします。

# 7. Te社RAG基盤で確認するポイント

gather、Semaphore、スレッドプール、プロセスプール、Workerの設定を確認します。各制限がどの範囲で共有されるか調べます。並列数と429、処理時間、メモリーの関係を記録し、詳細設計書の容量前提と照合します。
