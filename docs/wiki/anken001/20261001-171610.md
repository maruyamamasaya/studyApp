# 1. 概要

OpenID Connect（OIDC）は、OAuth 2.0を土台としてサインインの情報を伝える仕組みです。ID Tokenによって、クライアントアプリへ利用者の認証結果を伝えます。[Entra IDのOIDC](https://learn.microsoft.com/en-us/entra/identity-platform/v2-protocols-oidc)

# 2. 何のために使うか

RAGの画面で社内利用者のサインインを扱うために使います。APIの利用権限を示すAccess Tokenとは用途を分けます。

# 3. 仕組み

クライアントがopenid Scopeを含めて認証を開始し、認証後にID Tokenなどを受け取ります。署名、Issuer（発行者）、Audience（宛先）、有効期限、必要なnonce（要求と認証結果を結ぶ値）を検証します。Discovery情報には各種Endpointと公開鍵の場所などが記載されます。

# 4. 具体例

Te社の想定例で、画面はID Tokenを使ってサインイン状態を認識し、RAG API向けAccess Tokenを別に取得します。画面で表示名が見えていることと、質問APIが許可されることは別の判断です。

# 5. 実装・設定時のポイント

- ID Tokenは利用クライアント向けに検証します。
- state、nonce、PKCEのそれぞれの目的を確認します。
- Redirect URIを正確に登録します。
- 認証結果は対応ライブラリで検証し、単純なJSON解析で済ませないようにします。

# 6. 注意点

ID TokenのAudienceは画面などのClient IDである場合があり、質問APIのAudienceとは違います。表示名やメールアドレスは変更されることがあるため、認可の安定したキーとして無条件に使わないようにします。

# 7. Te社RAG基盤で確認するポイント

サインイン処理、openid Scope、ID Tokenの取得と保存、セッション生成を確認します。質問APIへ送信しているTokenの種類を追います。ログアウト、セッション期限、利用者無効化の扱いを設計書と照合します。
