## 1. Exponential Backoffとは

Exponential Backoff（エクスポネンシャル・バックオフ）は、

**Retryするたびに待ち時間を少しずつ長くする方法**

です。

例えば、

1回目の失敗  
→ 1秒待つ

2回目の失敗  
→ 2秒待つ

3回目の失敗  
→ 4秒待つ

4回目の失敗  
→ 8秒待つ

というように、待機時間を増やします。

---

## 2. なぜ待ち時間を増やすのか

APIやサーバーが一時的に混雑している場合、

失敗直後にすぐ再試行しても、また失敗する可能性があります。

そのため、

失敗  
→ 少し待つ  
→ Retry  
→ また失敗  
→ さらに長く待つ

という形にします。

サーバー側が回復する時間を確保できます。

---

## 3. 単純Retryとの違い

単純Retryでは、

失敗  
→ すぐRetry  
→ すぐRetry

となる場合があります。

これでは、障害中のサーバーへさらに大量のRequestを送ってしまう可能性があります。

Exponential Backoffでは、

**Retry間隔を広げることで負荷を抑えます。**

---

## 4. 基本イメージ

例えば、

```
1回目: 1秒待機
2回目: 2秒待機
3回目: 4秒待機
4回目: 8秒待機
```

のようになります。

計算イメージとしては、

```
待機時間 = 基準時間 × 2 ^ Retry回数
```

のような形です。

実装によって計算方法は異なります。

---

## 5. Pythonの簡単な例

```
import time


max_retries = 4

for attempt in range(max_retries):
    try:
        result = call_api()
        break

    except TemporaryError:
        wait_seconds = 2 ** attempt
        time.sleep(wait_seconds)
```

この場合、

0回目  
→ 1秒

1回目  
→ 2秒

2回目  
→ 4秒

3回目  
→ 8秒

と待機します。

---

## 7. Rate Limitとの関係

APIには、

「一定時間に何回まで」

というRate Limitが設定されていることがあります。

短時間に大量Requestを送ると、

HTTP 429 Too Many Requests

が返る場合があります。

その場合、

すぐRetryするのではなく、

Exponential Backoffで徐々に待機時間を増やします。

---

## 8. Retry-After

APIによっては、

Retry-After

というHTTP Headerが返されることがあります。

これは、

「何秒後にもう一度試してください」

というServer側からの指示です。

Retry-Afterがある場合は、

自分で計算したBackoffより、

Serverの指示を優先することがあります。

---

## 9. Jitter

複数Clientが同時に失敗すると、

全員が、

1秒後  
2秒後  
4秒後

という同じタイミングで再接続してしまう可能性があります。

そのため、少しランダムな時間を加えることがあります。

これを、

Jitter

と呼びます。

例えば、

4秒  
＋  
0〜1秒のランダム待機

のようにします。

---

## 10. Jitterが必要な理由

例えば100台のClientが同時にRate Limitされた場合、

全員が4秒後にRetryすると、

4秒後にまたRequestが集中します。

Jitterを入れると、

4.1秒  
4.5秒  
4.8秒

などに分散できます。

これによって再び負荷が集中するのを防ぎます。

---

## 11. 最大待機時間

待機時間を無制限に増やすわけではありません。

例えば、

最大30秒

などの上限を設定します。

```
wait_seconds = min(
    2 ** attempt,
    30
)
```

のようにします。

これによって、

1  
2  
4  
8  
16  
30  
30

のようになります。

---

## 12. 最大Retry回数

Exponential Backoffを使っても、

永遠にRetryしてはいけません。

例えば、

最大3回  
最大5回

などで終了します。

上限を超えたら、

エラーとして呼び出し元へ返します。

---

## 13. Timeoutとの関係

Exponential Backoffは、

Retry間隔

を決めます。

Timeoutは、

1回の処理を何秒待つか

を決めます。

例えば、

Timeout  
= 30秒

Retry  
= 最大3回

Backoff  
= 1秒 → 2秒 → 4秒

という組み合わせです。

---

## 14. すべてのエラーに使わない

例えば、

401 Unauthorized

が返っている場合、

API Keyが間違っている可能性があります。

この場合、

1秒  
2秒  
4秒

待っても直りません。

Exponential Backoffは、

**時間が経てば回復する可能性があるエラー**

に使います。

---

## 15. よくある対象

使いやすいのは、

- 429 Too Many Requests
    
- 502 Bad Gateway
    
- 503 Service Unavailable
    
- 504 Gateway Timeout
    
- 一時的な通信障害
    

などです。

ただし、実際には利用するAPIの仕様を確認します。

---

## 16. 一言で理解する

Exponential Backoffとは、

**「Retryするたびに待ち時間を長くして、サーバーへ負荷をかけすぎないようにする仕組み」**

です。

覚え方としては、

**失敗 → 1秒 → 失敗 → 2秒 → 失敗 → 4秒**

で十分です。

Retryとセットで、

**Retry + Exponential Backoff + Jitter + Timeout**

として覚えておくと実装で使いやすいです。
