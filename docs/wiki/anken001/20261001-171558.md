## 1. Circuit Breakerとは

Circuit Breaker（サーキットブレーカー）は、

**外部サービスで失敗が続いたとき、一時的にそのサービスへのアクセスを止める仕組み**

です。

例えば、

LLM API  
→ 失敗  
→ Retry  
→ 失敗  
→ Retry  
→ 失敗

と何度も失敗している場合、

「このサービスは今壊れている可能性が高い」

と判断して、一時的に呼び出しを止めます。

---

## 2. なぜ必要なのか

障害中のサービスへ何度もRequestを送り続けると、

- 待ち時間が増える
    
- Retryが大量発生する
    
- 自システムまで遅くなる
    
- 接続数を消費する
    
- 障害中のサービスへさらに負荷をかける
    

といった問題が起きます。

Circuit Breakerは、

**障害を他の処理へ広げない**

ために使います。

---

## 3. Retryとの違い

Retryは、

**一時的な失敗なので、もう一度試す**

仕組みです。

Circuit Breakerは、

**失敗が続いているので、しばらく試すのをやめる**

仕組みです。

つまり、

Retry  
＝ 再挑戦する

Circuit Breaker  
＝ 再挑戦そのものを一時停止する

という違いがあります。

---

## 4. 基本的な3つの状態

Circuit Breakerは主に、

- Closed
    
- Open
    
- Half-Open
    

の3状態で動きます。

---

## 5. Closed

通常状態です。

Circuit Breakerは閉じています。

Requestは普通に外部サービスへ送られます。

例えば、

Client  
→ Circuit Breaker  
→ LLM API

という流れです。

エラーが一定回数を超えると、

Open

へ移行します。

---

## 6. Open

障害が続いている状態です。

Circuit Breakerを開き、

外部サービスを呼び出さなくなります。

例えば、

Client  
→ Circuit Breaker  
→ 即エラー

となります。

LLM APIへRequest自体を送りません。

これによって、障害中のサービスへ負荷をかけ続けることを防ぎます。

---

## 7. Half-Open

一定時間が経過したら、

「サービスが復旧したか確認する」

ために少数のRequestだけ通します。

これがHalf-Openです。

例えば、

30秒間Open  
→ Half-Open  
→ 試しに1Request送信

します。

---

## 8. 復旧した場合

Half-OpenでRequestが成功した場合、

サービスが復旧した

と判断します。

Half-Open  
→ Closed

へ戻します。

その後は通常通りRequestを送ります。

---

## 9. まだ障害中の場合

Half-Openで試したRequestが再び失敗した場合、

まだ復旧していない

と判断します。

Half-Open  
→ Open

へ戻します。

そして、また一定時間待ちます。

---

## 10. 状態の流れ

基本的には、

Closed  
→ 失敗が一定回数発生  
→ Open  
→ 一定時間待つ  
→ Half-Open  
→ 成功  
→ Closed

または、

Half-Open  
→ 失敗  
→ Open

となります。

---

## 11. 具体例

例えば、

失敗回数の上限  
= 5回

Open時間  
= 30秒

とします。

LLM APIが、

5回連続失敗

したら、

Circuit BreakerをOpenにします。

その後30秒間は、

LLM APIを呼ばずに即エラー

を返します。

30秒後に1回試し、

成功すれば通常状態へ戻します。

---

## 12. RAGで使う場所

RAGでは例えば、

- LLM API
    
- Embedding API
    
- OCR API
    
- Search API
    
- Reranking API
    

などの外部サービスに使えます。

特に、

継続的に障害が発生する可能性がある外部サービス

で有効です。

---

## 13. Timeoutとの関係

Timeoutだけの場合、

毎回、

30秒待つ  
→ Timeout

を繰り返す可能性があります。

Circuit Breakerがあれば、

何回かTimeout  
→ 障害と判断  
→ Open  
→ 以降はすぐ失敗

にできます。

これによってユーザーの待ち時間を減らせます。

---

## 14. Retryとの組み合わせ

よくある構成は、

API呼び出し  
→ Timeout  
→ Retry  
→ Retry  
→ 連続失敗  
→ Circuit Breaker Open

です。

つまり、

Timeout  
→ 1回の待ち時間制限

Retry  
→ 一時失敗への再試行

Circuit Breaker  
→ 継続障害なら呼び出し停止

という役割分担です。

---

## 15. Exponential Backoffとの関係

Retryするときは、

Exponential Backoff

を使います。

例えば、

1秒  
2秒  
4秒

待ってRetryします。

それでも失敗が続く場合、

Circuit BreakerをOpen

にします。

---

## 16. Fallbackとの組み合わせ

Circuit BreakerがOpenになった場合、

別の処理へ切り替えることがあります。

これをFallbackと呼びます。

例えば、

Reranking API障害  
→ Circuit Breaker Open  
→ Rerankingを使わず検索結果をそのまま利用

といった構成です。

---

## 17. RAGでのFallback例

例えば、

LLM A  
→ Circuit Breaker Open

なら、

LLM Bへ切り替える

という構成もあります。

または、

「現在AI回答機能を利用できません」

と即時に返すこともできます。

---

## 18. Failure Threshold

Circuit BreakerをOpenにする基準を、

Failure Threshold

と呼ぶことがあります。

例えば、

連続5回失敗

や、

直近20Request中50%以上失敗

などです。

単純な連続失敗だけとは限りません。

---

## 19. Recovery Timeout

Open状態を何秒維持するか

を決める設定があります。

例えば、

Recovery Timeout = 30秒

です。

30秒経過後にHalf-Openへ移行します。

---

## 20. Pythonでのイメージ

概念的には、

```
if circuit_breaker.is_open():
    raise ServiceUnavailableError()

try:
    result = call_api()
    circuit_breaker.record_success()

except Exception:
    circuit_breaker.record_failure()
    raise
```

のような処理になります。

実際にはライブラリを使う場合もあります。

---

## 21. 自分で全部実装しなくてもよい

Circuit Breakerは、

- アプリケーションライブラリ
    
- API Gateway
    
- Service Mesh
    
- Proxy
    

などで実装されることもあります。

そのため、

Pythonコード内で必ず自作する

とは限りません。

---

## 22. Circuit Breakerがない場合

例えばLLM APIが完全に停止している状態で、

100ユーザー

が同時にアクセスしたとします。

全Requestが、

Timeout  
→ Retry  
→ Timeout  
→ Retry

すると、

自分のRAG APIまで負荷が高くなる

可能性があります。

Circuit Breakerがあれば、

障害検知後は即失敗

にできます。

---

## 23. Circuit Breakerの目的

重要なのは、

外部サービスを復旧させること

ではありません。

目的は、

**外部サービスの障害によって、自分のシステム全体まで不安定になるのを防ぐこと**

です。

---

## 24. 一言で理解する

Circuit Breakerとは、

**「外部サービスの失敗が続いたら、一旦呼び出すのをやめる仕組み」**

です。

覚え方としては、

**Closed = 通常**

**Open = 呼び出し停止**

**Half-Open = 復旧確認**

で十分です。

Retry系をまとめると、

**Timeout → Retry → Exponential Backoff → それでも失敗が続く → Circuit Breaker**

という流れで理解すると分かりやすいです。
