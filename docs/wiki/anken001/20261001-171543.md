# 1. 概要

Hybrid Search（ハイブリッド検索）は、キーワード検索とベクトル検索など、異なる方式の結果を組み合わせる検索です。名称の一致と意味の近さを同時に利用できます。

# 2. 何のために使うか

自然言語の言い換えと、型番・社内固有名詞の厳密な検索を両立するために使います。一方の方式に寄せるより根拠の候補を広く拾える場合があります。

# 3. 仕組み

Azure AI Searchでは、キーワードとベクトルの順位リストをRRF（Reciprocal Rank Fusion：順位に基づく統合）でまとめます。概念式は各リストの「1 /（定数 + 順位）」の合計です。この定数と、ベクトル検索の取得件数kは別の値です。検索スコアを単純に足しているわけではありません。[公式説明](https://learn.microsoft.com/azure/search/hybrid-search-ranking)

# 4. 具体例

Te社の想定例で「AUTH-001の解決方法」を検索する場合、コード一致をキーワードで拾い、関連するログイン障害手順をベクトルで拾います。両方の候補を統合した後に、必要に応じてRerankを行います。

# 5. 実装・設定時のポイント

- キーワードのみ、ベクトルのみ、統合後を同じ評価質問で比較します。
- ベクトル候補k、返却件数top、Contextに入れる件数を分けます。
- 各検索経路へ同じ権限条件を適用します。
- 順位付けの方式が変わった場合は、スコア閾値を再評価します。

# 6. 注意点

異なる方式のスコアは尺度が違います。統合後スコアと再順位付け後スコアも別物です。一部の経路だけが失敗した場合の扱いを決め、黙って品質が変わらないようにします。

# 7. Te社RAG基盤で確認するポイント

検索SDK呼び出しにsearch_textとvector_queriesの両方があるか確認します。RRF後の件数、Rerankの有無、filterの共有を調べます。設計書の「Hybrid」という記載を、実際のリクエスト内容で裏付けます。
