# 1. 概要

Cache（キャッシュ）は、以前の計算結果や取得結果を保存して再利用する仕組みです。RAGではEmbedding、検索結果、回答などが対象になりますが、再利用できる条件は対象ごとに違います。

# 2. 何のために使うか

繰り返し質問の待ち時間や外部APIの費用を減らすために使います。文書更新や権限変更によって結果が変わることを考慮し、安全に再利用できる範囲を決めます。

# 3. 仕組み

Cache-Asideでは、最初にキャッシュを探し、なければ元のサービスから取得して保存します。TTL（Time To Live）は保存を有効とする期間です。[公式パターン](https://learn.microsoft.com/en-us/azure/architecture/patterns/cache-aside)

RAGのキーには、質問だけでなく、利用者の権限範囲、文書世代、モデル、Prompt版などの必要な要素を含めます。

# 4. 具体例

Te社で総務の利用者に返した回答を、同じ質問をした別部署へそのまま返すと漏えいになり得ます。利用者または確定した権限範囲で分離し、権限変更時に再認可または無効化できるようにします。

# 5. 実装・設定時のポイント

- Embeddingキャッシュは本文とモデル・次元設定でキーを作ります。
- 検索・回答キャッシュは索引世代と認可条件を含めます。
- 更新、削除、失効時の無効化手順を決めます。
- ヒット率、古い結果の返却、容量と保存期間を観測します。

# 6. 注意点

TTLがあるだけでは、権限剥奪を即時反映できません。同じ質問でも会話履歴や適用日で回答が変わります。意味が似た質問を共有するSemantic Cacheは、微妙な条件差を見落とすリスクがあるため、別に評価します。

# 7. Te社RAG基盤で確認するポイント

キー生成、保存データ、TTL、削除処理、テナントと権限の分離を確認します。キャッシュヒット時にも必要な認可が実行されるか追います。文書削除後や部署変更後のテストを実施し、詳細設計書の更新反映時間と照合します。
