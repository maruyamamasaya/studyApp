# 1. 概要

Rerank（再順位付け）は、最初の検索で得た候補を、質問との関連性に基づいて並べ直す処理です。検索索引全体から新たな文書を探す処理とは区別します。

# 2. 何のために使うか

意味が似ているだけの候補より、質問へ直接答える候補を上位へ置くために使います。最初の検索で候補を広めに集め、再順位付け後に入力する根拠を絞ります。

# 3. 仕組み

質問と各候補の本文を再順位付けモデルへ渡して評価します。Azure AI SearchのSemantic rankerは初期検索結果の上位50件を対象とし、本文情報から順位を再評価します。検索索引全体から候補を補充するものではありません。Semantic answersもLLMによる自由な回答生成ではなく、索引からの抽出です。[公式説明](https://learn.microsoft.com/en-us/azure/search/semantic-search-overview)

# 4. 具体例

Te社の想定例で「申請の承認者は誰か」を検索すると、制度の概要より承認経路の説明が有用です。再順位付けでその説明を上位へ置き、回答の根拠へ使います。

# 5. 実装・設定時のポイント

- 対象の本文、タイトル、キーワードの設定を確認します。
- 初期検索の候補不足は、再順位付けだけでは解消できません。
- 再順位付けの追加時間と費用を測ります。
- 採用モデル、言語対応、サービスのリージョンとプランを確認します。

# 6. 注意点

Rerankスコアも正解確率ではありません。モデル更新で分布が変わる可能性があるため、細かすぎる固定閾値に依存しない評価を行います。機密文書を外部の再順位付けサービスへ送る場合は、許可された送信先か確認します。

# 7. Te社RAG基盤で確認するポイント

query_type、semantic_configuration_name、初期候補数、使用するスコアのキーを確認します。Rerank前後の順位差と回答品質を比較します。再順位付けが失敗した場合に初期順位を使うか、質問処理を失敗させるかを設計と照合します。
