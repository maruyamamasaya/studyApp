# 1. 概要

Azure AI Searchは、文書を索引化して検索できるAzureのサービスです。全文検索、ベクトル検索、Hybrid検索などを提供します。LLMが回答文を生成する役割とは分けて理解します。[公式概要](https://learn.microsoft.com/en-us/azure/search/search-what-is-azure-search)

# 2. 何のために使うか

社内資料から質問に関係する根拠を素早く取り出します。本文と一緒に出典や権限属性を持たせ、後段の回答生成に必要な情報を返します。

# 3. 仕組み

Index（索引）へ本文、ID、属性、ベクトルなどのフィールドを定義します。アプリが直接登録するPush方式や、Indexerが元データを読む方式があります。検索時には対象フィールド、検索文、ベクトル、Filter、返却件数を指定します。

# 4. 具体例

Te社の学習用例として、chunk_id、document_id、content、page、version、allowed_groups、content_vectorを持つ索引を考えます。実際のSchemaは索引定義と登録コードから確認します。

# 5. 実装・設定時のポイント

- key、searchable、filterable、retrievableなどの属性を確認します。
- ベクトル次元、解析器、Semantic configurationをコードと照合します。
- 質問APIは読取、取り込みWorkerは登録・更新の権限へ分けます。
- Schema変更時の再構築と切り替えを計画します。

# 6. 注意点

Searchサービスのアクセス権を持つことと、文書ごとの閲覧権限は別です。APIが広い読取権限を持つ場合は、利用者に応じた検索制限が必要です。管理キーを質問APIへ渡す設計は必要以上の権限になり得ます。

# 7. Te社RAG基盤で確認するポイント

索引定義、Indexer、Skillset、登録関数、SearchClient、Filter生成を確認します。削除文書と旧版が索引に残っていないか調べます。SKU、容量、認証方式、Private Endpointの利用は実設定から確認します。
