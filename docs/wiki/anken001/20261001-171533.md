# 1. 概要

RAG（Retrieval-Augmented Generation：検索拡張生成）は、質問に関係する資料を検索し、その内容を大規模言語モデル（LLM）に渡して回答を作る方法です。モデルの学習済み知識だけに頼らず、社内規程などの根拠を回答時に参照できます。

# 2. 何のために使うか

社内の新しい情報や、一般公開されていない情報について答えるために使います。モデル自体を追加学習することと、回答時に資料を与えることは別の操作です。更新頻度の高い資料は検索対象を更新する設計が適しています。

# 3. 仕組み

事前に文書を小さく分割して検索用の索引に登録します。質問時には関連部分を取り出し、質問と根拠を一緒にLLMへ送信します。回答には文書名・ページなどの出典を付け、利用者が内容を確認できるようにします。

検索が間違えば、生成する文章も間違いやすくなります。RAG全体の品質は、文書品質、検索品質、根拠の使い方の積み重ねです。

# 4. 具体例

Te社の学習用想定例として、「出張精算の締切はいつですか」という質問に、閲覧を許可された最新版の旅費規程を検索して回答します。規程に記載がない場合は「資料から確認できません」と返す設計にします。

# 5. 実装・設定時のポイント

- 回答の正しさ、根拠の正しさ、検索漏れを別々に評価します。
- 同じ質問でも利用者によって読める文書が違うため、検索時点で権限を適用します。
- 文書の更新・削除・権限変更を検索索引にも反映します。
- 検索結果が空の場合の応答を仕様に含めます。

# 6. 注意点

RAGを使っても誤った断定はなくなりません。出典が付いていても、その出典に回答内容が書かれているとは限りません。実際に根拠の該当箇所を照合する評価が必要です。

# 7. Te社RAG基盤で確認するポイント

質問APIの入口から検索・生成・回答整形までを追い、どの関数がどの段階を担当するか記録します。既存HTML資料が現在のコードと一致するか確認し、差分は「仕様変更」「資料未更新」「未確認」に分類します。実システムの採用方式はコードと設定で確定します。
