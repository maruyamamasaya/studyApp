## 1. RAGとは

RAG（Retrieval-Augmented Generation：検索拡張生成）は、LLMが回答を生成する前に、外部の文書やデータを検索し、その検索結果を参考情報としてLLMに渡す仕組みです。

ChatGPTなどのLLMは、基本的には学習時に覚えた知識を使って回答します。

RAGを利用すると、

- 社内資料
    
- マニュアル
    
- PDF
    
- FAQ
    
- 製品情報
    
- 最新情報
    

など、LLMが元々知らない情報を使って回答できるようになります。

---

## 2. RAGを使う理由

LLM単体では、次のような問題があります。

- 学習後の最新情報を知らない
    
- 社内情報を知らない
    
- 詳細な業務ルールを知らない
    
- 存在しない情報をもっともらしく回答することがある
    

そこで、質問に関連する資料を検索してLLMへ渡します。

例えば、

「出張費の申請期限は？」

という質問があった場合、社内の旅費規程を検索して、その内容をLLMに渡します。

LLMは自分の知識だけではなく、検索された旅費規程を根拠として回答します。

---

## 3. RAGの基本構成

RAGは大きく、

1. 文書を登録する処理
    
2. 質問に回答する処理
    

の2つに分けて考えると理解しやすいです。

### 3.1 文書登録

最初に検索対象となる文書を準備します。

例：

- PDF
    
- Word
    
- HTML
    
- Markdown
    
- Excel
    
- テキスト
    

文書からテキストを取得し、検索しやすい形に加工します。

---

### 3.2 Chunk

長い文書をそのまま検索対象にするのではなく、小さな文章単位に分割します。

この単位をChunk（チャンク）と呼びます。

例えば100ページのPDFを、

- 章
    
- 見出し
    
- 数百文字
    

などの単位に分割します。

Chunkが大きすぎると不要な情報が増え、小さすぎると文章の意味が失われる可能性があります。

---

## 4. Embedding

Embedding（エンベディング）は、文章の意味を数値の配列に変換する仕組みです。

例えば、

「パソコンを購入する」

と

「PCを買う」

は使用している単語が違いますが、意味はかなり近い文章です。

Embeddingを利用すると、このような意味の近さを数値として比較できます。

この数値データをVector（ベクトル）と呼びます。

---

## 5. Vector Search

質問もEmbeddingによってVectorに変換します。

そして、文書のVectorと質問のVectorを比較して、意味が近い文章を検索します。

これをVector Search（ベクトル検索）と呼びます。

例えば、

質問：

「パソコンを買う場合の申請方法は？」

検索結果：

「PC購入時は上長の承認を受けてください」

単純な文字検索では見つけにくい場合でも、意味が近ければ検索できます。

---

## 6. RAGの処理フロー

基本的な処理は次のようになります。

### 文書登録時

文書取得  
→ テキスト抽出  
→ Chunk分割  
→ Embedding  
→ Vector DB / 検索エンジンへ登録

### 質問時

ユーザーの質問  
→ 質問をEmbedding  
→ 関連文書を検索  
→ 関連するChunkを取得  
→ 質問とChunkをLLMへ渡す  
→ LLMが回答生成  
→ 回答と出典を返す

つまりRAGでは、

「検索」

と

「生成」

が組み合わされています。

---

## 7. Vector DB

EmbeddingしたVectorを保存して検索するために、Vector検索に対応したデータベースや検索サービスを利用します。

代表例として、

- Azure AI Search
    
- Elasticsearch
    
- OpenSearch
    
- Pinecone
    
- Weaviate
    
- Milvus
    
- PostgreSQL + pgvector
    

などがあります。

RAGでは必ず専用のVector DBが必要というわけではなく、Vector検索に対応した検索サービスやデータベースを利用できます。

---

## 8. Prompt

検索した文書をそのまま回答として返すのではなく、質問と検索結果をLLMへ渡します。

イメージとしては、

「以下の資料を参考に質問へ回答してください」

という指示と一緒に、

- ユーザーの質問
    
- 検索したChunk
    

をLLMへ渡します。

このLLMへ渡す指示や情報をPrompt（プロンプト）と呼びます。

RAGではPromptの作り方も回答品質に大きく影響します。

---

## 9. Hallucination

Hallucination（ハルシネーション）は、LLMが事実ではない内容をもっともらしく回答してしまう現象です。

RAGを利用すると、根拠となる資料をLLMへ渡せるため、Hallucinationを減らすことができます。

ただし、RAGを利用してもHallucinationが完全になくなるわけではありません。

例えば、

- 間違った文書を検索した
    
- 古い資料を検索した
    
- 必要な資料を検索できなかった
    
- LLMが資料にない内容を追加した
    

といった問題が発生する可能性があります。

そのため、

「RAG = 必ず正しい回答になる」

というわけではありません。

---

## 10. Keyword SearchとVector Search

RAGではVector Searchだけでなく、通常のKeyword Searchも使用できます。

### Keyword Search

入力された単語と一致する文章を検索します。

例えば、

「Windows Server 2025」

という単語が含まれる文書を検索します。

製品名、型番、エラーコードなどの検索に強い方式です。

### Vector Search

文章の意味が近いものを検索します。

例えば、

「PCを購入したい」

と

「パソコンの購入方法」

のように、違う単語でも意味が近い文章を検索できます。

---

## 11. Hybrid Search

Keyword SearchとVector Searchを組み合わせる方式をHybrid Searchと呼びます。

RAGではよく利用される方式です。

例えば、

製品名やエラーコード  
→ Keyword Searchが得意

自然な質問  
→ Vector Searchが得意

という違いがあります。

両方を組み合わせることで、検索精度を高めます。

---

## 12. Reranking

最初の検索結果を、そのままLLMへ渡すとは限りません。

例えば検索結果として20件取得し、その中から質問との関連性が高い5件を再評価して選ぶことがあります。

この処理をReranking（リランキング）と呼びます。

処理イメージは、

検索  
→ 候補20件  
→ Reranking  
→ 上位5件  
→ LLM

となります。

検索結果の品質を改善するために利用されます。

---

## 13. Metadata

文書には本文だけでなくMetadata（メタデータ）を持たせることがあります。

例えば、

- ファイル名
    
- 文書ID
    
- 作成日
    
- 更新日
    
- 部署
    
- カテゴリ
    
- ページ番号
    
- URL
    
- 権限情報
    

などです。

Metadataを利用すると、

「2026年以降の文書だけ検索する」

「自分の部署の資料だけ検索する」

といった絞り込みができます。

---

## 14. 権限制御

社内RAGでは特に重要な要素です。

検索対象に機密情報が含まれている場合、ユーザーが閲覧できない文書を検索結果に含めてはいけません。

そのため、

ユーザー  
→ 認証  
→ 権限確認  
→ 閲覧可能な文書だけ検索

という制御を行います。

回答生成後に隠すのではなく、検索段階からアクセスできない文書を除外することが重要です。

---

## 15. RAGで重要なポイント

RAGの品質はLLMだけで決まりません。

主に、

- 元文書の品質
    
- テキスト抽出
    
- Chunkの分け方
    
- Embedding
    
- 検索方式
    
- 検索件数
    
- Metadata
    
- Reranking
    
- Prompt
    
- LLM
    

などが関係します。

そのためRAGでは、

「LLMが賢いか」

だけではなく、

「正しい情報を検索できているか」

が非常に重要です。

---

## 16. RAGとFine-tuningの違い

RAGとFine-tuningは別の技術です。

### RAG

外部情報を検索して、回答時にLLMへ渡します。

向いているもの：

- 社内資料
    
- 最新情報
    
- 頻繁に更新される情報
    
- 大量の文書
    

### Fine-tuning

追加データを使ってモデル自体の振る舞いを調整します。

向いているもの：

- 回答形式
    
- 文体
    
- 特定タスクの振る舞い
    
- 出力パターン
    

知識を追加したい場合は、まずRAGを検討することが多いです。

---

## 17. RAGを理解するための重要用語

|用語|意味|
|---|---|
|RAG|検索結果を利用してLLMに回答させる仕組み|
|LLM|大規模言語モデル|
|Chunk|文書を分割した単位|
|Embedding|文章の意味を数値化する処理|
|Vector|Embeddingによって作られた数値データ|
|Vector Search|意味の近さで検索する方式|
|Keyword Search|単語の一致を利用する検索|
|Hybrid Search|Keyword検索とVector検索の組み合わせ|
|Vector DB|Vectorを保存・検索できるDBや検索サービス|
|Metadata|文書に付与する補助情報|
|Reranking|検索結果を再評価して並び替える処理|
|Prompt|LLMへ渡す指示や入力|
|Hallucination|LLMが誤情報を生成する現象|
|Fine-tuning|モデル自体を追加学習・調整する方法|

---

## 18. 一言で理解する

RAGは、

**「LLMにいきなり質問するのではなく、先に資料を検索して、その資料をカンニングペーパーとしてLLMに渡して回答させる仕組み」**

と考えると理解しやすいです。

RAGを学ぶうえでは、

**Chunk → Embedding → Search → Reranking → Prompt → LLM**

という一連の流れを理解することが基本になります。
