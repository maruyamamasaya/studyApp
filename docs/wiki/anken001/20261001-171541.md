# 1. 概要

Vector Search（ベクトル検索）は、質問のベクトルに近い文書ベクトルを探す検索です。文字列の一致だけでなく、表現の意味的な近さを利用します。

# 2. 何のために使うか

利用者が文書中の正確な用語を知らなくても、関係する根拠を探せるようにします。社内用語の言い換えには役立ちますが、型番や番号の厳密な一致には別の検索方式も必要です。

# 3. 仕組み

全件比較する厳密検索と、近い候補を効率よく探す近似最近傍検索があります。HNSWはベクトル間のつながりを使って候補をたどる方式の一つです。Azure AI Searchではベクトルフィールドと検索設定を定義し、質問ベクトルを渡します。[クエリの公式説明](https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-query)

# 4. 具体例

Te社の想定例では、「会社のPCをなくした」という質問に対して「端末紛失時の連絡手順」を検索します。関連度が高くても別部署専用の資料なら、権限条件によって除外します。

# 5. 実装・設定時のポイント

- ベクトル次元、距離尺度、検索プロファイルを照合します。
- 上位件数とMetadata Filterの適用方式を分けて確認します。
- 正解根拠が候補内にある割合を測り、速度と両立させます。
- 同一文書の似たChunkばかりになる場合は重複を調整します。

# 6. 注意点

Top-Kだけ指定すると、無関係でも近い順に候補が返ることがあります。検索スコアをそのまま正解確率として表示してはいけません。フィルターの適用タイミングにより候補が不足する場合があるため、権限条件込みで評価します。

# 7. Te社RAG基盤で確認するポイント

索引のvectorフィールド、dimensions、metric、検索クエリのkを確認します。質問Embeddingの生成元と一致するか、filterの適用モードを指定しているか調べます。実際の質問で正解根拠が何位に入るか記録します。
