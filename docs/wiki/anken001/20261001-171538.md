# 1. 概要

OCR（Optical Character Recognition：光学文字認識）は、画像中の文字をテキストに変換する技術です。スキャンされたPDFや画像では、通常の文字抽出だけでは本文を取得できないため利用します。

# 2. 何のために使うか

画像中心の社内資料を検索対象へ取り込むために使います。OCRの誤りは検索と回答へ連鎖するため、取り込み段階で品質を確認する必要があります。

# 3. 仕組み

画像を解析し、文字列と位置を推定します。サービスによっては信頼度（認識結果に対する確からしさの指標）や表構造も返します。Azure Document IntelligenceのLayoutモデルは文字に加えて表や文書構造を抽出します。[公式説明](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/layout)

# 4. 具体例

Te社の古い申請書を想定し、「0」と「O」や、数字の小数点の誤認識を検査します。申請番号や金額が誤って認識された箇所は、原本と照合して修正するか、検索対象から外す判定を設けます。

# 5. 実装・設定時のポイント

- 対応言語、解像度、回転、手書き、ページ制限を確認します。
- 長時間処理では受付レスポンスと解析完了を区別し、結果取得の待機を管理します。
- サービスのモデル・API版と、評価用サンプルを固定します。
- ページ単位で品質を評価し、低品質資料を運用担当者へ戻します。

# 6. 注意点

信頼度が高くても、業務上重要な文字が正しいとは限りません。数字や製品番号は別の評価が必要です。画像を拡大するだけでは元画像にない情報は復元できず、再スキャンが適切な場合もあります。

# 7. Te社RAG基盤で確認するポイント

OCR対象の判定、送信するデータ範囲、解析結果の保存場所、失敗時の再試行を確認します。処理件数だけでなくページ数と費用も追えるか調べます。OCR利用サービスの存在は、クライアント生成とAzure設定で確定します。
