> Te社向けの例は学習用の想定です。実際の採用サービス・設定・権限は、既存コードと正式資料で確認してください。

# 1. 概要

Top-K（トップケー）は、順位が高い候補をK件取り出す考え方です。RAGには複数の段階があるため、どの段階で何件を選ぶかを明示する必要があります。

# 2. 何のために使うか

検索漏れ、応答時間、LLMの入力容量のバランスを取るために使います。候補を広く集めてから、少数の根拠を選ぶ構成もあります。

# 3. 仕組み

ベクトル検索の候補数、統合後の返却件数、Rerankへ渡す件数、Contextへ入れる件数は別です。たとえば候補50件から再順位付けを経て5件をContextへ入れる、という学習用設定を考えられます。数値は固定の正解ではなく評価で調整します。

# 4. 具体例

Te社の規程を想定すると、5件の候補がすべて同じページの重複Chunkでは、例外条項を拾えません。単純な件数だけでなく、異なる根拠の数と入力Token数を確認します。

# 5. 実装・設定時のポイント

- 設定名にretrieval_k、context_limitなど役割が分かる名前を使います。
- Kを増やした時の正解根拠の回収率と処理時間を測ります。
- Token予算を超える場合は、件数より先に入力容量を制約として扱います。
- 権限フィルターや重複除去後の残件数を記録します。

# 6. 注意点

Kを増やすと、無関係な情報や矛盾する旧版を含める危険も増えます。取得件数が多いほど正しい回答になるとは限りません。Azure AI Searchのkとtopは異なる意味を持つため混同しないようにします。

# 7. Te社RAG基盤で確認するポイント

設定ファイル、検索呼び出し、配列のスライス、Context構築処理の各件数を追います。詳細設計書の取得件数がどの段階の値か確認します。設定未指定時のSDKやサービスの既定値も、採用版の仕様で確認します。
