## 1. 全体方針

個人開発は、単純にアプリの数を増やす段階から、それぞれのアプリの役割を明確にし、AI・クラウド・デバイス連携を使って発展させる段階に入りつつある。

特に今後は、AIチャットそのものを再開発するのではなく、以下を重視したい。

- AIが裏側で継続的に動く仕組み
    
- iPhone / Mac / Windowsなど複数端末との連携
    
- 既存アプリ同士のデータ連携
    
- AIによる整理・提案・自動処理
    
- 3D・VRなど通常のAIチャットでは実現しにくい体験

## 2. 現在のアプリ・領域

### 2.1 タスク管理

通常のタスク管理だけではなく、AIを活用したタスク管理へ発展させたい。

候補機能：

- 自然文からタスク生成
    
- 優先順位の提案
    
- 今日やるタスクの絞り込み
    
- 長期間放置されたタスクの再評価
    
- SecondBrainなどからタスク候補を抽出
    
- Mac / iPhone間の同期
    

単なるTodoアプリではなく、「整理する作業そのものを減らす」方向を検討する。

### 2.2 音楽

現在比較的うまくいっている領域。

新機能を大量に追加するより、現在の仕組みを安定させて日常的に使える状態を維持する。

yt-dlpについてはPython環境ごとのバージョン差があるため、将来的には実行環境を統一したい。

### 2.3 動画

まだ方向性を決め切れていない。

ローカル動画を大量管理する方式は容量や管理コストの問題があるため、YouTubeなど既存サービスを利用しつつ、自分専用の動画管理UIを作る案がある。

例：

- URLだけ保存
    
- おすすめ動画を表示しない
    
- Shortsなどを排除
    
- 自分が登録した動画だけを見る
    
- AIによる分類・要約
    
- 後で見る動画の自動整理
    

「動画サービスを作る」のではなく、「自分が選んだ動画だけを見る環境」を作る方向が候補。

### 2.4 写真・生成AI作品

HomeMuseumは比較的うまく進んでいる。

今後は通常の写真管理とは別に、

- 日常写真
    
- 作品写真
    
- AI生成画像
    
- スクリーンショット
    
- その他のデジタル作品
    

などを整理する仕組みも検討したい。

HomeMuseumとは別に、iCloudを活用した日常写真アプリも将来的な候補。

などをAIが提案する方向が面白い。

将来的にはSecondBrainやRAGとの連携も検討する。

## 3. 新規構想：My Space

今回、新しい長期プロジェクト候補として「My Space」の構想が出てきた。

### 3.1 コンセプト

My Spaceは、自分のデジタル生活とともに成長する、自分専用の永続3D空間。

最初から都市を作るのではなく、小さな自分の部屋から開始する。

将来的には、

My Room  
→ My House  
→ My Building  
→ My Space

のように拡張できる構造を目指す。

### 3.2 空間と既存データの連携

3D空間の各場所に、自分のデジタルデータを対応させる。

- Desk：開発・タスク
    
- Bookshelf：SecondBrain / Study
    
- Gallery：写真 / AI生成画像
    
- Theater：動画
    
- Music Space：音楽
    
- AI Room：AI・実験
    
- Museum：HomeMuseumとの連携
    

単なる3Dゲームではなく、「自分のデジタルデータを空間として触るUI」を目指す。

### 3.3 Unity

3D部分はUnityを中心に検討する。

主な要素：

- GameObject
    
- Component
    
- Prefab
    
- Material
    
- Texture
    
- 3D Model
    
- C#
    
- Scene
    
- Camera
    
- Input
    
- XR / VR
    

3Dモデルや家具などは、最初から自作せず既存Assetを活用する。

AIコーディングではC#、JSON、API、ロジックなどを中心に扱い、Scene、Prefab、Materialなど視覚的な部分はUnity Editorで確認する。

### 3.4 AWS

My Spaceの最初のバージョンではAWSを必須にしない。

初期：

Unity  
→ JSON / SQLite  
→ ローカル保存

将来：

Unity  
→ AWS  
→ 複数デバイスから同じMy Spaceへアクセス

AWS候補：

- Cognito：認証
    
- API Gateway：API
    
- Lambda：処理
    
- DynamoDB：世界の状態
    
- S3：画像・3Dデータ
    
- EventBridge：定期処理
    
- SQS：非同期処理
    
- Step Functions：複雑な処理
    
- CloudWatch：監視
    
- Bedrock / 外部AI API：AI
    

### 3.5 Background AI

My Spaceで特に重要なテーマ。

「AIを24時間実行し続ける」のではなく、「システムが常に変化を監視し、必要なタイミングでAIを起動する」。

基本構造：

発火  
→ 状況取得  
→ AI判断  
→ 処理  
→ 状態保存

例：

- 新しい写真が追加された
    
- 新しいメモが作られた
    
- GitHubへPushされた
    
- 一定時間が経過した
    
- データの関連性が変化した
    
- しばらく利用されていない情報がある
    

AIが裏側で整理・分析し、次にMy Spaceへ入ったときに空間が変化している体験を目指す。

## 6. AI開発で改善したいこと

AIコーディングでは「作れること」と「使いやすいこと」は別問題。

現在は実装速度が大きく上がっている一方、実際に日常的に使えるレベルまでUI / UXをブラッシュアップする工程に時間がかかっている。

今後は、

- 小さい機能単位で実装
    
- 実際に毎日使う
    
- 不便な点を記録
    
- AIへ改善を依頼
    
- 再度使う
    

という短い改善サイクルを重視する。

また、AIが変更しやすい部分と、人間が確認すべき部分を分離する。

## 7. 今後の大きな方向性

現在の個人開発は、それぞれ次の役割に分かれつつある。

- SecondBrain：知識
    
- Study App：学習
    
- Task：行動
    
- HomeMuseum：作品・写真
    
- Music：音楽
    
- Video：映像
    
- My Space：3D体験・統合空間
    

最終的にすべてを無理に一つのアプリへ統合する必要はない。

それぞれのアプリを専門ツールとして維持しながら、必要なデータだけ共有し、My Spaceのような新しいUIから横断的にアクセスできる構造を目指す。

特に今後の研究テーマとして、

**「人間が操作していない時間にAIに何をさせると価値が生まれるのか」**

を継続して考える。

AIそのものを再開発するのではなく、AIを既存アプリ・データ・3D空間・クラウドと組み合わせることで、ChatGPT単体では作りにくい体験を作ることを目標とする。
